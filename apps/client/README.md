# VoiceChat prototype

Flutter-клиент для Android и web. Запуск и ограничения: [лаборатория E2EE](../../prototype/README.md).

`lib/main.dart` — ручной прототип с темами Lavender Soft, Ocean Calm и Midnight.
`lib/lab_main.dart` — отдельный автоматический сквозной сценарий на одноразовых аккаунтах.

Android и мобильный web используют общую адаптивную компоновку Lavender Soft. В узком чате поле ввода, голосовое сообщение и отправка всегда на виду; кнопка «+» раскрывает фото, файлы, эмодзи, временные и отложенные сообщения и видеокружки. На широком экране действия остаются в одной строке.

Сравнение экранов: [галерея до / после](../../docs/design/mobile-refresh/index.html). Проверки узких экранов и клавиатуры — `flutter test test/mobile_layout_test.dart`; сценарий снимков — `integration_test/design_gallery_test.dart` (только одноразовый аккаунт `ui_*` из локального fixture, без реального захвата микрофона и камеры).


### Доработки Lavender Soft от 23 октября

Android и сайт используют общий интерфейс из `lib/`: экран звонка с аватаром, пульсацией входящего вызова, таймером и пятью делениями качества; компактные сообщения и список чатов; выделенные голосовые карточки; копирование идентификаторов; карточки устройств; диаграмма локальной копии; нижняя панель группы; русская локализация календарей. Свободный объём в настройках относится к лимиту локальной копии, а не к диску целиком.

Обязательные задачи и проверка: [список](../../docs/design/mobile-refresh/tasks.md). Новые проверки: `flutter test test/design_refinements_test.dart test/call_window_test.dart`. Сборка общего веб-интерфейса: `flutter build web`; публикация на основной сайт требует отдельного развёртывания.

Сборки Android и веба запускайте последовательно: Flutter перегенерирует общий `GeneratedPluginRegistrant.java`, а release web исключает тестовый плагин. Для снимков каждой платформы нужен отдельный новый аккаунт `ui_*`, так как сценарий создаёт собственную группу «Семья».


### Основной сайт и очереди

`python3 prototype/serve_app.py` из корня проекта запускает обычный сайт :7357 вместе с обязательным API :8090. [Итерация 6](../../docs/iterations/06-main-site-and-send-queue.md) описывает исправление временных сообщений и строку «Запланировано · N» под поиском. Она открывает очередь с датами, статусами и расшифрованным на устройстве содержимым; отправленные и отменённые задания в счётчик не входят.

[Итерация 7](../../docs/iterations/07-voice-waveform-and-motion.md) обновляет RMS-шкалу записи (окна по 50 мс), оттенок плеера, цвета собственных голосовых в списке, отступы времени и шапки до краёв окна. Общие переходы панелей/окон/страниц — около 180 мс, с поддержкой уменьшения движения. Проверки: `flutter test test/voice_waveform_test.dart test/app_motion_test.dart test/conversation_list_test.dart`. [Снимки и ограничения проверки](../../docs/design/mobile-refresh/voice-update/index.html).

## Демонстрация экрана (экспериментальная)

Клиент использует отдельный ScreenShareController текущего VoiceCall и существующие
Matrix/LiveKit подключения. ScreenCapture подготавливается из пользовательского
нажатия до claim; ключи идут только encrypted Matrix to-device. В UI есть отдельный
screen view, takeover/stop/fullscreen и Auto/Low. Server capability по умолчанию off.
[Инструкция](../../docs/screen-sharing.md), [матрица приёмки](../../docs/screen-sharing-acceptance.md).
Android service подготовлен, аппаратная проверка отложена; mobile web в закреплённом
SDK имеет только просмотр. Не включать функцию в релиз по одному успешному build.

## Регистрация в браузере

«Создать аккаунт» открывает форму без предварительного открытия локального хранилища. Пользователь задаёт пароль аккаунта и подтверждает почту. Имя профиля и ключ шифрования браузерной базы создаются автоматически. После регистрации приложение создаёт E2EE identity и резервную копию ключей, показывает аварийный ключ восстановления. При выходе с незавершённой формы клиент закрывается. Проверка: `flutter test test/registration_screen_test.dart` и `node prototype/check_signup_ui.cjs` из корня с Playwright в NODE_PATH.

### Доработки локальной проверки Halo

[Список задач](../../docs/tasks/halo-local-polish.md), [снимки профиля, групп и размытия](../../docs/design/halo-polish/index.html). Общий `showAppDialog` сохраняет фокус, закрытие и результаты стандартного диалога и добавляет плавное размытие фона. Дату и время оборачивает тот же `AppModalBackdrop`. Цвета ников группы и цитат назначаются детерминированно по набору участников; для изменённого состава палитра пересчитывается. Проверки: `flutter test test/halo_polish_test.dart`. Снимки: `flutter test --dart-define=HALO_POLISH_CAPTURE=true test/halo_polish_capture_test.dart`.

Цитаты имеют отдельное визуальное выделение, которое сбрасывается по щелчку на фон или при уходе исходного сообщения за экран в сторону новых сообщений. Повторный переход не пересоздаёт чат и сохраняет черновик; «Вернуться к новым сообщениям» остаётся отдельным действием. Реакции используют строку фиксированной ширины с зарезервированной высотой, зависящей от масштаба текста. Дополнительные проверки: `flutter test test/halo_iteration_test.dart test/quote_navigation_test.dart test/photo_viewer_test.dart test/scheduled_layout_test.dart`.

Дата добавления устройства записывается в account data `dev.voicechat.device.added.<encoded device ID>` только после нового входа или регистрации. Это метаданные интерфейса, а не доказательство доверия к устройству. Повторное открытие сессии дату не меняет; для старых устройств без записи показано «дата не сохранена», последняя активность отображается отдельно. Ошибка записи этих необязательных метаданных не отменяет успешный вход.

Локальный запуск после сборки: из корня `python3 prototype/serve_app.py --port 7362`, с `http://localhost:7362` и `http://127.0.0.1:7362` в `VOICECHAT_ORIGINS` API. Команда обслуживает web и API вместе; данные существующего локального Docker Compose сохраняются.

Изменения мобильного общения от 25.10.2026: [задачи и границы приёмки](../../docs/tasks/14-mobile-calls-and-messaging.md).
В регистрации логин автоматически приводится к строчным a–z. Кружок начинает
запись по нажатию; «Отправить» завершает и сразу отправляет. При удержании
отпускание отправляет, сдвиг влево отменяет; прерывание сохраняет черновик.
Видеозвонок показывает собеседника крупно, своё видео — маленьким в углу с
кнопкой скрытия (камера продолжает передачу). На web при блокировке аудио
нажмите «Включить звук». Push включается отдельно в настройках; на iPhone —
из webapp на домашнем экране. Требования сервера: [infra/README.md](../../infra/README.md).
Новые группы используют общую историю; для передачи старых ключей новому
участнику нужна независимая проверка устройства. История, отправленная при
старой политике joined, задним числом не открывается и не переносится.

## macOS / Apple Silicon

Ветка macOS использует тот же `lib/main.dart`, темы и адаптивные экраны. Целевая
система — **macOS 12+ на arm64 (M1 и новее)**. macOS 11 не входит в текущий
контракт: закреплённый Flutter runner и Sparkle 2.10 требуют 12. Поддержка Intel
не заявлена. Фактические результаты и непроверенные сценарии:
[журнал macOS](../../docs/iterations/15-macos.md), [план](../../docs/tasks/15-macos.md).

Сборка требует Xcode, CocoaPods и Flutter из `infra/crypto-tools.json`.
Flutter-плагины подключаются CocoaPods; Sparkle закреплён отдельным SPM package.
Использовать `LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8`, а не `LC_ALL=C`.
Cargokit вызывает Rust stable; его версия должна совпадать с `rust` из того же JSON.
Для сборки нужен запас свободного дискового места для Xcode, Flutter и Rust.

Из корня, задав `PUBLIC_URL` каноническим HTTPS origin нужного сервера:

```sh
python3 infra/client_config.py "$PUBLIC_URL" /tmp/voicechat-macos.json
cd apps/client
../../.prototype/tools/flutter/bin/flutter pub get --enforce-lockfile
../../.prototype/tools/flutter/bin/flutter run -d macos --target lib/main.dart --dart-define-from-file /tmp/voicechat-macos.json
```

Для release заменить `run -d macos` на `build macos --release`.
Результат: `apps/client/build/macos/Build/Products/Release/VoiceChat.app`.
Автономный ручной workflow **macOS checks and candidate** проверяет общий клиент,
реальные Keychain/SQLCipher на одноразовом профиле, XCTest и release-сборку.
Он создаёт **development** DMG/ZIP; без Developer ID/notarization это не
пользовательский дистрибутив и не кандидат для публикации обновления.

```sh
python3 infra/macos_release.py --app apps/client/build/macos/Build/Products/Release/VoiceChat.app --output /tmp/voicechat-macos-candidate
```

Для файлов используются NSOpenPanel/NSSavePanel; запись завершается атомарной
заменой после успешной загрузки. Камера/микрофон требуют системного разрешения.
Видео YouTube открывается внешним браузером. Закрытие окна оставляет процесс
работать; Dock возвращает окно. Cmd+Q завершает процесс, после этого системные
уведомления не приходят. Уведомления включаются отдельно для аккаунта, не содержат
текст сообщения и открывают чат только текущей сессии.

Профиль хранится в sandbox контейнере `dev.voicechat.client`; точный каталог БД
выбирает sqflite. Ключ SQLCipher — в login Keychain, временные записи — в
`Library/Caches/VoiceChatRecordings` контейнера. Установщик меняет `.app`, а не
контейнер или Keychain. Нельзя менять bundle ID/Team ID между выпусками или удалять
контейнер для «починки» обновления. Физическая проверка сохранности профиля N → N+1
обязательна перед публикацией.

Обновления доступны через «О приложении → Проверить обновления». Нет фоновой
проверки, загрузки или установки. Sparkle проверяет подписанный feed и архив;
во время звонка/записи/отправки установка блокируется. Незаданные Xcode settings
`VOICECHAT_UPDATE_FEED` и `VOICECHAT_UPDATE_PUBLIC_KEY` оставляют канал выключенным.
[Подпись, упаковка и публикация](../../infra/MACOS.md).
