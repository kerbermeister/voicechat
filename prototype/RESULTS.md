Итоговые локальные проверки: `flutter analyze` — без замечаний, `flutter test` — 2 теста, Python unittest — 3 теста; обычные APK/debug и web собраны без лабораторных define-файлов.

Среда: Flutter 3.47.7, Dart 3.13.5, Matrix SDK 14.2.0, flutter_vodozemac 0.9.0, LiveKit Flutter 2.13.1, LiveKit Server 1.13.10; эмулятор Google APIs Android 15 ARM64 и Headless Chrome 155 на macOS. Web использовал синтетический микрофон; Android — виртуальный аудиотракт. Android соединялся со SFU по ICE/TCP через adb reverse, Chrome — по локальному UDP.

Каждый web-участник тестируется в своей вкладке: WebRTC worker сопоставляет крипторы по track ID, поэтому два независимых клиента в одном JS-контексте создают неоднозначность. Для проверки допуска устройства используется `DeviceKeys.encryptToDevice` при `ShareKeysWith.crossVerified`: SDK проверяет цепочку до master key владельца. Это не заменяет ручную проверку личности/SAS.

Успешная расшифровка подтверждает совместимость клиентов, но не является аудитом криптографии. Не проверены намеренная подмена медиаключа, отзыв участника и ротация эпох, десять участников, качество реального микрофона/эхоподавления, блокировка экрана, push и восстановление после смены сети. GitHub Actions подготовлен, но на GitHub не запускался. Production-деплой не выполнялся.
