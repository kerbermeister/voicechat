# Локальный прототип E2EE

Это лаборатория на одноразовых аккаунтах, а не готовый мессенджер. Основной клиент находится в `apps/client/lib/main.dart`, автоматический сценарий — в `lib/lab_main.dart`. Используются настоящие Synapse, Matrix SDK/vodozemac и LiveKit. Медиа-ключи передаются через зашифрованные Matrix to-device события; сервер выдачи JWT их не получает.

Сохранение веб-входа и новый интерфейс: [итерация 4](../docs/iterations/04-web-session-and-lavender.md).

Первый прототип и его границы: [RESULTS.md](RESULTS.md). Актуальная приёмка основного клиента: [итерация 3](../docs/iterations/03-core-messenger.md), [обезличенные этапы](verified-core-run.json).

## Инструменты

Проверяемая конфигурация: Flutter 3.47.7 / Dart 3.13.5, JDK 21, Android SDK 36, эмулятор Android 35 ARM64 с Google APIs, Docker Compose, Python 3. Flutter SDK вне репозитория; системный Flutter не заменяется. Версии Dart-зависимостей закреплены `pubspec.lock`, образы — digest в Compose.

Для web нужны Rust stable и nightly с rust-src, `flutter_rust_bridge_codegen` 2.13.0, `wasm-pack`, `wasm-bindgen-cli` 0.2.100. Нативные библиотеки Android собирает пакет flutter_vodozemac; нужен Rust в PATH. На macOS используйте `LC_ALL=en_US.UTF-8 LC_CTYPE=en_US.UTF-8 LANG=en_US.UTF-8`: системный Perl/shasum из Cargokit не поддерживает `C.UTF-8`.

## Запуск локальных серверов

Из корня репозитория:

```sh
python3 prototype/setup.py
docker compose -f prototype/compose.yaml up -d
python3 prototype/seed.py
python3 prototype/token_server.py
```

Дождаться ответа `http://localhost:8008/_matrix/client/versions` перед seed. Пароли для ручной проверки находятся в `.prototype/accounts.json`; весь каталог исключён из Git. Последняя команда работает в отдельном терминале. Контейнеры доступны только через loopback. `docker compose ... down` сохраняет данные; `down -v` уничтожает их, включая историю и резервные копии ключей.

```sh
cd apps/client
flutter pub get
cd ../..
python3 prototype/build_web_assets.py
cd apps/client
flutter build web
cd ../..
python3 prototype/serve_web.py
```

Открыть `http://localhost:7357`. Регистрация и восстановление пароля используют локальную почту: `http://localhost:8025`. При первом входе локальную фразу придумывает сам пользователь; у seed-аккаунтов заранее заданной фразы нет.

Для офлайн-доставки демо-пользователям после первого запуска обычного web-клиента выполнить `node prototype/activate_demo.cjs` из корня с доступным Playwright. Скрипт активирует только `bob`/`carol`, у которых ещё нет E2EE-ключей, через настоящий клиент, сохраняет их зашифрованные браузерные профили и закрывает браузеры. Материалы локальных демонстрационных устройств находятся только в игнорируемом `.prototype/demo-devices/`; не публиковать их. Это подготовка тестовых аккаунтов, не серверная генерация ключей для обычных пользователей. Новое устройство такого аккаунта проходит обычное доверие/восстановление истории.

Обычная веб-сборка открывает зашифрованный профиль отдельной локальной фразой (от 12 символов); кнопка «Заблокировать» закрывает хранилище без отзыва сессии. Сервер выставляет COOP/COEP для WASM. В обычном клиенте доступны регистрация, поиск пользователей и личные/групповые чаты, текст/изображения/голосовые, правки/ответы/реакции/удаление, поиск истории, очередь и входящие вызовы в открытом интерфейсе. Ручной ввод идентификатора звонка больше не нужен. Подробности и ограничения — [итерация 3](../docs/iterations/03-core-messenger.md). Ключ восстановления показывается пользователю; не сохранять его в Git или логах. Lavender Soft — начальная тема, Ocean Calm и Midnight переключаются и сохраняются локально.

## Android ↔ web: сквозной сценарий

Эмулятор должен быть запущен заранее. Для этого локального стенда медиа идут через ICE/TCP и adb reverse; это не проверка реальной мобильной сети.

```sh
adb reverse tcp:8008 tcp:8008
adb reverse tcp:8090 tcp:8090
adb reverse tcp:7880 tcp:7880
adb reverse tcp:7881 tcp:7881
adb reverse tcp:3478 tcp:3478
python3 prototype/prepare_run.py
cd apps/client
flutter build web --target lib/lab_main.dart --dart-define-from-file=../../.prototype/web.json --output=../../.prototype/lab-web
flutter build apk --debug --target lib/lab_main.dart --dart-define-from-file=../../.prototype/android.json --target-platform android-arm64
adb install -r build/app/outputs/flutter-apk/app-debug.apk
adb shell pm grant dev.voicechat.voicechat_probe android.permission.RECORD_AUDIO
adb shell am start -n dev.voicechat.voicechat_probe/.MainActivity
```

Лабораторный web запускать отдельно: `python3 prototype/serve_web.py --port 7358 --directory .prototype/lab-web`. Открыть две вкладки `http://localhost:7358/` и `http://localhost:7358/?role=carol` в Chrome с доступом к микрофону (для автоматического запуска: `--use-fake-device-for-media-stream --use-fake-ui-for-media-stream --autoplay-policy=no-user-gesture-required`). Порт 7357 остаётся обычным приложением. Затем из корня:

```sh
python3 prototype/check_reports.py
```

Сценарий проверяет двустороннюю расшифровку текста Android ↔ web и отсутствие текста в серверном событии; останавливает старые клиенты; входит новым устройством; отвергает неверный recovery key и восстанавливает оба сообщения правильным ключом. Проверяются также офлайн-очередь, правки/ответы/реакции/удаление, файлы, typing/receipts, запись/воспроизведение и личный WebRTC через TURN с подтверждённым DTLS и входящими аудиопакетами. Затем три участника (Android + два web-клиента в отдельных вкладках) должны получить подтверждение расшифровки каждого удалённого аудиопотока через событие cryptor `kOk`. До отправки проверяются отказ непроверенным устройствам, несовпадающий отпечаток и сохранение доверия при повторном открытии профиля. Одного успешного подключения к SFU недостаточно для PASS. Затем сценарий проверяет отзыв старого устройства: неверный пароль отклоняется, правильный отзывает токен, все три клиента завершают звонок, старый ключ не расшифровывает новое сообщение, а оставшиеся участники его получают.

Каждый повтор начинается с `prepare_run.py` и пересборки **обоих** клиентов. Не распространять лабораторные сборки: в них вкомпилированы одноразовые тестовые пароли. Обычные сборки используют `lib/main.dart` без define-файлов.

Отдельный быстрый прогон видео использует те же свежие fixtures, но target `lib/lab_video_main.dart` для обеих платформ; проверять через `python3 prototype/check_video_reports.py`. Он требует реальные `framesDecoded`, успешные крипторы каждого удалённого потока, TURN/DTLS в личном вызове, переключение/выключение камеры Android и получение 180p с возвратом Auto. Для камеры также выдать тестовому APK `android.permission.CAMERA` до запуска.

Сетевой UI-прогон: `VOICECHAT_VIDEO_TEST=1 VOICECHAT_NETWORK_TEST=1 node prototype/check_contacts_ui.cjs`. Используется [глобальная эмуляция WebRTC Chrome DevTools](https://chromedevtools.github.io/devtools-protocol/tot/Network/#method-emulateNetworkConditionsByRule): ограничения пропускной способности/12% потерь, затем восстановление и отдельный короткий HTTP-offline. Это эмуляция, не поездка между реальными Wi-Fi/мобильными сетями.

## Границы прототипа

- HTTP/WS, локальный издатель JWT и диагностические `/report` предназначены исключительно для loopback. Для VPS требуются HTTPS/WSS, производственная авторизация и деплой по архитектуре.
- Android-хранилище защищено SQLCipher/Keystore; веб-вход использует парольный vault. Веб-хранилище (включая лабораторию) зашифровано отдельной фразой; [описание итерации 2](../docs/iterations/02-web-vault-and-device-verification.md). Обновление со старого plaintext-профиля и точные границы описаны в [итерации 1](../docs/iterations/01-local-keys-and-revocation.md). Только тестовые данные.
- Перед передачей ключей требуется ручная сверка отпечатков устройств через независимый канал; доверие хранится локально. SAS/QR ещё нет. В лаборатории публичные отпечатки передаются отдельным fixture-каналом `/report`; это автоматизированная проверка механизма, не проверка человека.
- Ключ отправителя уникален на подключение, привязан к комнате/сессии/устройству и передаётся только текущим участникам. При изменении доступа обновлённые клиенты завершают звонок. Производственная смена эпохи, принудительный отзыв на SFU и защита от гонок требуют отдельного протокола. Текущий звонок нельзя использовать для секретных разговоров.
- Push/фоновые звонки, производственное восстановление соединений и остальные незавершённые работы перечислены в [общем статусе](../docs/implementation-status.md). Основные сценарии переписки и регистрации реализованы для локального стенда.
- Эмулятор с синтетическим звуком не подтверждает качество микрофона, эхоподавление, Bluetooth, работу под блокировкой, десять участников или нестабильную сеть.

## Проверки веб-хранилища

При доступном Playwright (`NODE_PATH`) и запущенном Chrome/serve_web:

```sh
node prototype/test_web_vault.cjs
node prototype/check_turn.cjs
# После полного лабораторного прогона, Chrome CDP localhost:9223:
node prototype/check_web_records.cjs
```

Первый тест использует отдельный временный браузерный контекст. Второй проверяет форму всех значений IndexedDB только у текущих одноразовых профилей и выводит количество записей, без содержимого. Полный прогон также проверяет гонку «медленное чтение / новая запись» в кэше SDK.

## Почтовая проверка

`python3 prototype/check_registration.py` проверяет обязательность подтверждения почты, регистрацию, восстановление пароля и отказ старому паролю. Одноразовые данные созданного аккаунта сохраняются в `.prototype/registered-account.json`, без вывода паролей в консоль. Mailpit — исключительно локальная тестовая почта.

## Обычный пользовательский интерфейс

После обычной `flutter build web` (без lab target), при доступном Playwright:

```sh
python3 prototype/check_registration.py
# For repeated UI runs, avoid exhausting the separate email verification rate limit:
python3 prototype/prepare_ui.py
node prototype/check_ui.cjs
node prototype/check_contacts_ui.cjs
node prototype/check_signup_ui.cjs
```

Для каждого повторения создаётся свежий одноразовый аккаунт: закрытие браузера после неудачного UI-теста не заменяет отзыв устройства. Сценарий использует семантическое дерево Flutter, проверяет каталог/группу, текст/изображение/микрофон/плеер, правку/реакцию, настройки, узкую компоновку, lock/unlock/logout. Снимки и снимок ошибки остаются в `.prototype/ui/` (вне Git). В репозитории сохранены только выбранные снимки с тестовыми данными в `docs/design/screenshots/`.

В новом интерфейсе перед тестовым вводом имени профиля раскройте «Параметры подключения». Устройства, ключи истории, темы, блокировка и выход находятся в «Настройки». Для тестов снова нужен свежий аккаунт после неуспешного прогона, оставившего Matrix-устройство.

При ограничении нагрузки использовать только `VOICECHAT_QUOTE_ONLY=1 node prototype/check_ui.cjs` после подготовки одного свежего UI fixture. Эта ветка проверяет текст, правку/реакцию, переход к цитате с прокруткой вниз и сообщения о ненастроенном backup; завершается до изображений, микрофона, камеры и звонков. Сборку и браузерный сценарий запускать последовательно.

Для диагностики старой истории существующих локальных демо-аккаунтов: `node prototype/check_alice_history.cjs`. Нужны `.prototype/accounts.json`, сохранённые Bob/Carol профили с их vault fixtures и обычная web-сборка на 7357. Скрипт читает существующие базы, проверяет расшифровку в памяти, выводит только счётчики; ciphertext проверяется в ограниченной выборке, не во всей истории. `node prototype/sync_demo_history.cjs` отдельно открывает **сохранённое устройство Боба**, получает ожидающие to-device события и закрывает браузер. Это изменяет его время активности и локальную синхронизацию; новые входы технически заблокированы. Не запускать одновременно с другим браузером, использующим тот же fixture profile. Повторный аудит покажет, появились ли дополнительные старые ключи. Эти инструменты не переносят ключи в текущую Элис и не подтверждают устройства.

С 22 октября восстановление прежней истории Элис снято владельцем с текущей работы. Для новых примеров используйте `node prototype/prepare_demo.cjs`: нужны тот же локальный стенд, обычная web-сборка и Playwright в `NODE_PATH`. Скрипт последовательно готовит 15 аккаунтов `demo_*`, E2EE-устройства, ключи восстановления, согласия контактов, группы и зашифрованные сообщения. Камера, микрофон, пользовательский Chrome и нагрузочные тесты не используются. Повторный запуск продолжает подготовку по `.prototype/demo-suite.json`; не запускайте два экземпляра одновременно. Локальные профили сохраняются в `.prototype/demo-suite-devices/`.

Единый файл для ручного входа — `.prototype/DEMO-ACCOUNTS.md` (права `0600`, вне Git). В нём пароли, локальные фразы, имена профилей, ключи восстановления и сценарии проверки. В новом браузере после входа восстановите ключи через настройки: один пароль аккаунта старую E2EE-историю не открывает. Старые аккаунты и данные скрипт не удаляет. Эти демо-учётные записи нельзя переносить на производственный сервер.

## Видеосвязь и плохая сеть

`VOICECHAT_VIDEO_TEST=1 node prototype/check_contacts_ui.cjs` проверяет реальные кадры личного и группового видео, выключение камеры и ограничения Low/Auto. Для сетевой приёмки сначала собрать одноразовый диагностический образ `docker build -t voicechat-netem:test -f prototype/netem.Dockerfile .`, затем запустить с дополнительным `VOICECHAT_NETWORK_TEST=1`. Проверка временно ограничивает **только локальные** контейнеры TURN/SFU через `NET_ADMIN`: 384 кбит/с общего egress, 8% потерь, задержка 60 мс. Обычное завершение и ошибки снимают qdisc в `finally`; принудительное убийство процесса требует вручную удалить `tc qdisc del dev eth0 root` в том же сетевом namespace. Не запускать этот сценарий на стенде с чужими активными звонками.

Для сквозного видеопрогона создать свежие fixtures `python3 prototype/prepare_run.py`, собрать `lib/lab_video_main.dart` для web в `.prototype/lab-web` и Android с соответствующими `.prototype/web.json`/`android.json`. Web обслуживается на 7358, обычный клиент 7357 не заменяется лабораторным. Запустить `node prototype/check_video_web.cjs`, установить APK на emulator-5554 с CAMERA/RECORD_AUDIO и проверить `python3 prototype/check_video_reports.py`. Определение `--dart-define=BACKGROUND_TEST=true` на обеих сборках дополнительно проверяет Home/пересоздание Activity, непрерывные аудиопакеты и возврат камеры; web-драйвер сам восстанавливает `always_finish_activities=0`. Публичные результаты сохраняются без секретов, лабораторные APK с fixture-аккаунтами не распространяются.


### Лёгкие проверки допуска и резервной копии

`NODE_PATH=<каталог node_modules с Playwright> node prototype/check_lease.cjs` использует один собственный headless Chromium, настоящий локальный SFU/Matrix и изолированный временный control API. Предварительно на `localhost:7358` должна быть собрана/запущена лаборатория `lib/lab_revocation_main.dart`. Проверяются 30-секундный lease, отказ Matrix (инъекция на границе API), принудительное отключение и replay до истечения JWT. Захват камеры/микрофона запрещён; этот сценарий не проверяет медиарасшифровку. Временная SQLite удаляется, одноразовый аккаунт деактивируется. Результат без секретов: `verified-lease-run.json`.

`python3 prototype/check_backup.py --database-only` работает только с отдельным локальным Compose-стендом восстановления; он отказывается работать при активных writers. Запускает только его PostgreSQL, проверяет encrypted Restic snapshot и импортирует dump во временную базу, сверяет конфиги/signing key и SQLite integrity. PostgreSQL, запущенный этой проверкой, останавливается при выходе. Полное восстановление приложения этим режимом не заявляется.


Временные сообщения: `python3 prototype/check_temporary.py` проверяет реальное серверное истечение opaque fixture и запрет продления через правку. `VOICECHAT_TEXT_ONLY=1 VOICECHAT_SKIP_LINKS=1 VOICECHAT_TEMPORARY_TEST=1 node prototype/check_contacts_ui.cjs` проверяет реальную E2EE-расшифровку, таймер, reload и поиск на 390 px; нужен NODE_PATH с Playwright. Не запускает звонки/микрофон. `VOICECHAT_TEXT_ONLY=1 VOICECHAT_LINKS_ONLY=1` выбирает отдельную короткую диагностику видеокарточек, не повторяет всю проверку контактов. Последняя пока не принята; её результат не подменять результатом проверки сообщений.
