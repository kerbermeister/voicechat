# Halo: вход и аккаунт

Обновление в `codex/halo-design`. Общие Flutter-экраны для Android и веба; без слияния с основной веткой и без публикации на VPS.

[Обзор экранов](index.html) · [Локальная веб-сборка](http://localhost:7362/)

## Изменения

- Удалена старая WelcomePanel с демонстрационной перепиской. Вход стал самостоятельным адаптивным экраном с центральной карточкой Halo.
- Регистрация разделена на профиль и доступ, подтверждение почты вынесено в отдельный шаг. Возврат «Изменить данные» сохраняет ввод; новый запрос почтового токена увеличивает `sendAttempt`.
- Восстановление пароля использует одну колонку и явное предупреждение о завершении сессий и необходимости ключа восстановления.
- Общие `AuthPage`, `AuthField`, `AuthNotice`, `AuthStage` объединяют оформление, автозаполнение, показ пароля, ошибки и переходы. Формы прокручиваются при открытой клавиатуре; увеличенный текст переводит парные поля в колонку. Режим reduced motion полностью отключает переход шага.

## Центрирование

Сама карточка каждой формы расположена по центру доступной области окна по обеим осям. Шапка находится отдельно над ней и уравновешена свободным местом снизу, поэтому не сдвигает центр карточки. В `auth_fit_test.dart` координаты центра `auth-card` проверяются с точностью 0,5 px на семи размерах для входа, регистрации, восстановления и подтверждения почты. При нехватке высоты сохраняется доступная прокрутка.

## Умещение по высоте

Начальные формы и подтверждение почты помещаются без прокрутки при обычном размере текста на проверенных размерах 320×568, 390×667, 390×844, 320×844, 768×700, 1366×768 и 1440×900. На низких экранах убраны декоративная строка, вводный подзаголовок и избыточные подписи разделов; все поля и действия сохранены. Адреса подключения открываются отдельным окном по значку настроек в шапке. Прокрутка остаётся доступна при клавиатуре, увеличенном тексте, ошибках и дополнительных полях локального хранилища.

`auth_fit_test.dart` проверяет нулевую максимальную прокрутку и видимость кнопок без предварительной прокрутки, включая шаг email. Геометрия измеряется с рабочим Roboto, а не широким тестовым Ahem. После доработки прошли 11 целевых тестов авторизации и отдельный тест снимков.

## Сохранённые контракты

Сервер подтверждает email через Matrix UIA (`sid`, `clientSecret`, `session`). Проверки имени, почты, длины и совпадения паролей сохранены. Опциональная отдельная локальная фраза продолжает проверяться до открытия хранилища. Сохранены ленивое открытие клиента, обработка ошибок хранилища, установка отображаемого имени и `onRegistered` для существующей настройки ключей. При восстановлении по-прежнему передаётся `logoutDevices: true`.

Вход сохраняет восстановление сессии, обязательное подтверждение нового устройства, выбор темы и все три адреса подключения. Аутентифицированные экраны и серверные реализации не перерабатывались в этой итерации.

## Результат

До доработки высоты 167 тестов прошли, 2 опциональных теста снимков пропущены в общем запуске. Снимки авторизации запущены отдельно и получены успешно. Анализатор не нашёл замечаний; release web собран. Сборщик сохранил предупреждения зависимостей о Wasm dry run и отсутствующем семействе CupertinoIcons; стандартная JS-сборка завершилась успешно.

После доработки высоты Chrome: переходы вход → регистрация → вход → восстановление прошли на 1440×900, 1366×768, 390×844, 390×667 и 320×568, без JavaScript-ошибок и горизонтального переполнения документа. Координаты нижних кнопок проверены до прокрутки: все находятся внутри окна. Анализатор без замечаний, release web пересобран. Формы в браузерной проверке не отправлялись.

## Воспроизведение проверки

Из `apps/client`, SDK проекта:

```sh
../../.prototype/tools/flutter/bin/flutter analyze --no-pub
../../.prototype/tools/flutter/bin/flutter test --no-pub
../../.prototype/tools/flutter/bin/flutter test --no-pub --dart-define=AUTH_CAPTURE=true test/auth_capture_test.dart
../../.prototype/tools/flutter/bin/flutter build web --no-pub
```

Из корня: `python3 prototype/serve_web.py --port 7362`. Для браузерной проверки: `node docs/design/halo-auth/verify.cjs` с Playwright в `NODE_PATH` и установленным Google Chrome.

`auth_flow_test.dart` проверяет локальную валидацию без сетевого запроса, возврат с сохранением данных и повторный токен, UIA-сессию при ошибке, logoutDevices и формы при масштабе текста 200%, открытой клавиатуре, reduced motion на размерах 320×568, 844×390 и 1440×900.

Снимки `desktop-*` и `mobile-*` созданы из рабочих компонентов в widget-тесте на вымышленных данных. Они показывают начальные формы целиком на соответствующем размере экрана. `web-*` — снимки реальной веб-сборки в Chrome. `verification.json` содержит результаты браузерной проверки.

Не проверено: доставка реального письма и полный серверный вход/сброс в этой итерации, физический Android и плавность на реальном устройстве. Тестовые клиенты подтверждают контракт вызовов, но не заменяют сквозную проверку с сервером.
