# Отложенная задача: перенос доступного core A на другой VPS

Статус: **отложено владельцем 30 октября 2026**. Исходный ID V3-22 и критерий
HA-19 сохранены. Задача не входит в завершение текущего этапа «один VPS с core
и edge-a, новые входы добавляются конфигурацией». Выполнять её сейчас не нужно.

## Назначение и границы

Подготовить управляемый переезд на заменяющий VPS, пока исходный A доступен:
например, при смене хостинга. Постоянная рабочая копия данных остаётся одна;
временное копирование во время переезда не является постоянной репликацией.
Это не перенос edge-роли и не обязательный шаг подключения B/C/D/E.
Реальный production A не требуется переносить ради разработки или проверки.
Потерю недоступного диска покрывает отдельная будущая задача внешнего backup.

## Исходный объём V3-22

Зависимости: V3-06, V3-19, V3-20.

- [ ] Подготовить bootstrap core и согласованный перенос PostgreSQL, Synapse
  identity/media/config, всех control SQLite и нужных runtime/release данных.
- [ ] Остановить writers, перенести данные на новый A, проверить до включения
  записей, переключить B/C и изолировать старый A.
- [ ] Сохранить server_name, signing key, service ID и совместимость старых сессий.
- [ ] Разделить rollback до первой новой записи и после неё: после записи нужен
  обратный согласованный перенос, а не возврат адреса на устаревшую базу.

Проверка: два изолированных core-хоста на тестовых данных; одна активная пишущая
сторона, прежний device, история/файлы, новый звонок, прерывание переноса по фазам.
Выход: проверенный runbook переноса. Реальный production A переезжать ради этой
задачи не обязан; потерю его диска покрывает только будущий внешний backup.

## Безопасное завершение

Сначала испытать переход и прерывания на двух изолированных тестовых core-хостах.
Не использовать основной пользовательский профиль как fixture и не восстанавливать
устаревшую копию поверх новых записей. После успешного стенда подготовить отдельный
план production-переезда с адресами и окном; не запускать его как побочный smoke test.
Пользовательская приёмка остаётся в [едином реестре](../user-acceptance.md).
