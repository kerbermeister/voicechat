# Одноразовая ссылка в контакты

Ветка: `codex/contact-invite`; работа начата от `856bcd0`, перед завершением включён актуальный `main` (`bca6c9a`, 25 октября 2026, 07:23:33 +01:00).

## Пользовательский сценарий

В «Мой профиль → Пригласить по ссылке» или в окне приглашений владелец
создаёт ссылку для одного человека. Кнопка «Поделиться» открывает системное
меню Android (`ACTION_SEND`, `text/plain`) или Web Share API браузера: пользователь
выбирает мессенджер и адресата. Повторное нажатие использует ту же ссылку.
Если браузер не поддерживает системное меню, доступно копирование по нажатию
на ссылку. Отмена меню не расходует приглашение и не считается отправкой.
Получатель открывает ссылку
в веб-клиенте; после входа и подключения устройства доступна карточка
приглашения. В Android и вебе ссылку также можно вставить через
«Приглашения → У меня есть ссылка».

Карточка показывает Matrix-адрес владельца. Только кнопка
«Добавить и отправить „Привет“» закрепляет приглашение за аккаунтом,
добавляет взаимный контакт и публикует E2EE-приветствие от получателя.
Открытие, проверка и предпросмотр ссылки согласия не дают.
Общие настройки входящих обоих пользователей сохраняются.

## Контракт и хранение

`POST /contact-links` в существующем control API требует Matrix Bearer token:

| action | Поля | Результат |
| --- | --- | --- |
| `create` | — | Случайный `token`, 256 бит; не более 100 ссылок в сутки на владельца |
| `inspect` | `token` | `id`, `owner`, `claimed`, `accepted`, `room_id`, `prepared`, `event_id`; без записи |
| `claim` | `token` | Закрепление за одним аккаунтом после явного подтверждения, до создания комнаты |
| `accept` | `token`, `room_id` | Проверка настоящего зашифрованного личного Matrix-чата и атомарное принятие |
| `greet` | `id`, при первой отправке `payload`, `audience` | Подтверждённый Matrix `event_id` |

Ссылка имеет вид `https://<сервер>/#/contact/<token>`. Секрет находится во
фрагменте URL, поэтому не попадает в запрос страницы и HTTP Referer.
Клиент принимает только ссылку своего origin. Саму ссылку следует передавать
лично: первый подтвердивший её аккаунт становится получателем.
Срок действия и отзыв не добавлены в эту итерацию.

В существующем `contacts.sqlite` добавляется таблица `contact_links`.
Она хранит SHA-256 токена, владельца, получателя, комнату и квитанцию отправки.
`BEGIN IMMEDIATE` сериализует закрепление получателя; принятие контакта
и привязка комнаты фиксируются вместе. Повтор того же аккаунта возвращает прежнюю комнату;
другой аккаунт получает `link_used`, включая конкурентные запросы.
Существующая запись контакта обновляется без дублирования.
До создания новой комнаты клиент резервирует ссылку за аккаунтом. Новая комната
получает постоянный alias `voicechat-contact-<id>`: если ответ `createRoom` потерян,
клиент восстанавливает её ID по alias вместо создания второго чата. Комната остаётся
приватной; alias не разрешает посторонним вступление или получение ключей.

Первый зашифрованный конверт приветствия и устройство отправителя сохраняются
до публикации. Повторы, в том числе с другого устройства аккаунта, используют
тот же конверт и постоянный идентификатор. Переиспользован внутренний
Synapse publisher отложенных сообщений: он проверяет аккаунт, устройство,
членство, согласие контакта и состав ключей, а также возвращает прежнее событие
после потери ответа. После подтверждения ciphertext удаляется из таблицы,
`event_id` остаётся. Сервер не расшифровывает текст; текст «Привет» задаёт клиент.

После нажатия подтверждения токен незавершённого действия сохраняется
в зашифрованной локальной базе. Ошибка остаётся видимой; повтор кнопки или
повторное открытие после входа продолжает действие. Фоновая отправка при
закрытом клиенте не предусмотрена. Если ключи изменились до публикации,
приветствие отклоняется явно, а уже добавленный контакт сохраняется.

## Проверки и выпуск

- `prototype/test_contacts.py`: закрытые входящие, предпросмотр, гонка двух
  соединений, повтор/перезапуск, существующий контакт, сохранение первого
  устройства и конверта.
- `prototype/test_token_server.py`: аутентификация, чужой аккаунт, настоящая
  пара участников/шифрование, отказ plaintext, потеря ответа и повтор.
- `apps/client/test/contact_link_test.dart`: разбор origin/фрагмента, повтор
  сохранённого конверта, явное согласие, все темы, 320 px и текст 200%, вызов
  платформенного меню с существующей ссылкой.
- `prototype/check_contact_links.cjs`: обычный веб-клиент и настоящий локальный
  Synapse; PASS — `prototype/verified-contact-links-run.json`. Проверены потеря ответа
  создания комнаты, потеря ответа публикации, повтор без дубликатов, настоящая
  расшифровка «Привет» у обоих участников, отказ другому аккаунту и reload.
- 25 серверных тестов — PASS; адресные Flutter-тесты и `flutter analyze` — PASS.
  Release web и debug APK arm64 собираются. Перед приветствием состояние новой
  комнаты полностью загружается из локальной базы SDK: таймлайн ещё не открыт,
  и без этой загрузки проверка видимости истории не получала нужное состояние.

Серверная схема и control API изменены: для выпуска нужен `mode=full`.
Новые сервисы, зависимости или тома не добавлены; таблица входит в существующее
резервирование базы контактов. Старый клиент продолжает работать через прежний API.
Внешний VPS и физический Android требуют отдельной проверки. Ссылка на Android
открывает веб-клиент; автоматический переход из браузера в APK не реализован.
Проверка Web Share API с подменённым системным обработчиком проверяет данные,
user activation, отмену и fallback, но не отправку в реальный мессенджер.
