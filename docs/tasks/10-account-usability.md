# Ключ восстановления, мобильные настройки и устройства

Итерация 25 октября 2026; ветка `codex/recovery-key-export`.

## Ключ восстановления

Первое подключение устройства и создание ключа через настройки используют одно
окно. Ключ находится в подписанном поле только для чтения: можно выделить его,
скопировать кнопкой или сохранить как `voicechat-recovery-key.txt` (UTF-8,
`text/plain`). Содержимое файла — точная строка ключа без служебных заголовков.

Android переиспользует системный ACTION_CREATE_DOCUMENT и обработчик
`voicechat/save`: выбор, запись, закрытие; временного plaintext-файла в кеше нет.
При ошибке записи существующий обработчик удаляет незавершённый документ.
Веб использует существующий File System Access picker, когда он доступен.
Fallback — маленький локальный Blob без streaming worker или отправки ключа
на сервер. В этом случае сообщение «Файл передан браузеру. Проверьте загрузки»
не обещает подтверждённое сохранение на диск.

Отмена не выдаётся за успех. Копирование подтверждается после Clipboard API,
сохранение через picker — после записи и закрытия. Ошибки остаются видимыми,
ключ доступен для повторной попытки. Во время сохранения окно не закрывается.
Есть короткое предупреждение о секретном содержимом; имя файла и сообщения
об ошибках ключа не содержат.

## Мобильные настройки

При ширине менее 500 px уменьшены нижние отступы content/actions и убран
дополнительный buttonPadding. Нижняя область с «Закрыть» занимает не более
64 px, кнопка сохраняет целевой размер не меньше 44 px. Список прокручивается
независимо; верхняя кнопка закрытия остаётся. Проверено при 320×568 и тексте 200%.

## Устройства аккаунта

Новые входы и регистрация получают читаемое Matrix device display name.
Android сообщает производителя, системную модель и версию Android через
нативный API без новой зависимости. Веб определяет доступные тип устройства,
ОС и браузер из User-Agent. Полный User-Agent не сохраняется.

При восстановлении существующей сессии уточняется только прежнее общее имя
текущего устройства (VoiceChat, браузер, Android). Пользовательские имена и
записи других устройств не переписываются. Ошибка необязательного API названий
не прерывает успешный вход.

MacBook нельзя достоверно отличить от другого Mac по браузеру; номер модели
iPhone обычно недоступен, современные Android UA часто содержат только `K`.
В таких случаях используется доступный тип без выдуманного номера модели.
Старые общие имена других устройств показываются как «модель не определена»,
пока соответствующее устройство не подключится новым клиентом.

## Проверки и границы

- `recovery_key_dialog_test.dart`: точные UTF-8 байты, декодирование синтетического
  ключа через SDK, read-only поле, копирование, сохранение, отмена, ошибки записи
  и закрытия, 320×568 и текст 200%.
- `settings_footer_test.dart`: высота нижней области и кнопки, прокрутка и закрытие.
- `device_name_test.dart`: типы/браузеры, скрытые модели, пользовательские имена,
  изменение только текущего устройства и ошибка сети.
- Повторяются клиентские тесты входа/регистрации, навигации приглашений и анализ.

Физические Android/iPhone/MacBook и реальное меню сохранения на них требуют
отдельной проверки. Успешная сборка APK не заменяет проверку устройства.
Автоматический вход после подтверждения почты записан отдельной TODO.
