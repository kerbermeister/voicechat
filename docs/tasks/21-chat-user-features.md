  уже открыт, применять то же правило при автоматической отметке нового
  сообщения прочитанным. Повторное открытие чата или чтение с другого

- [x] Сделать явную особую анимацию появления/раскрытия такого сообщения

  сообщений со сроком от отправки. Во время отсчёта явно показывать режим
  и оставшееся время. По окончании проигрывать отдельную анимацию стирания

  понятный статический индикатор режима.
- [x] После истечения задержки удалять сообщение из доступной переписки

## Доработка — поле сообщения всегда готово к вводу (29 октября 2026)

Основное требование владельца: **вошёл в чат — курсор уже в «Написать
сообщение», и можно печатать в любой момент**. Это постоянное состояние
открытой переписки, а не восстановление ввода только после определённых
кликов. Любые обычные нажатия и действия внутри чата не должны оставлять
его без готового поля ввода. Модальные окна — явное исключение; после их
закрытия готовность к печати восстанавливается автоматически.

- [x] При открытии личной переписки или группы автоматически устанавливать
  фокус и курсор в поле «Написать сообщение», чтобы можно было сразу печатать
  без дополнительного клика. При наличии сохранённого черновика сохранять его
  содержимое и ставить курсор в конец текста.
- [x] После отправки сообщения сохранять или возвращать фокус в поле ввода,
  чтобы следующее сообщение можно было начать сразу. Проверить отправку
  клавиатурой и кнопкой: клик по кнопке отправки не должен оставлять поле
  без фокуса.
- [x] Сохранять готовность к вводу при обычных обновлениях переписки, но
  не перехватывать фокус, если пользователь явно перешёл в поиск, другое
  поле, меню или диалог. При смене чата ввод должен попадать в поле именно
  открытого чата.
- [x] На компьютере постоянно поддерживать фокус и курсор в поле сообщения
  с момента открытия чата, независимо от того, по каким элементам этого
  чата пользователь затем нажимал. История, фон, прокрутка, кнопки и обычные
  действия не должны требовать повторного клика в «Написать сообщение»:

## Доработка — цитирование сообщения с цитатой без рекурсии (29 октября 2026)

- [x] Исправить ответ на сообщение, которое само содержит цитату.
  По сообщению владельца, сейчас вместо выбранного сообщения может цитироваться
  предыдущий оригинал, а в превью появляются служебные знаки, ник и некорректное
  оформление. Причина исправлена: превью использовало `body` с fallback предыдущей цитаты,
  теперь берётся собственное содержимое непосредственного адресата ответа.
- [x] Для цепочки A → B → C, где B отвечает на A, а C отвечает на B,
  в C показывать автора и собственное содержимое B, без вложенной цитаты A,
  рекурсивного раскрытия цепочки и служебной разметки ответа. Переход по цитате
  должен открывать B, а не A; имя автора должно отображаться штатно, без
  дублирования ника или идентификатора из служебного текста цитаты.
