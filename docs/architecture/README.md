## Принятые технические решения

1. Один VPS, Docker Compose, GitHub Actions; PostgreSQL один, с раздельными БД и ролями сервисов.
2. Flutter-клиент для Android и веба. Общая логика, платформенные адаптеры для звонков, хранения и уведомлений.
3. Matrix/Synapse — источник истины для аккаунтов, членства в чатах и событий переписки. Федерация в первой версии отключена. Matrix SDK отвечает за криптографический протокол.
4. Go control-service — собственный модульный сервис управления звонками и их push-уведомлениями. Отдельных микросервисов для каждого действия нет.
5. Личные вызовы — WebRTC с TURN; группы — LiveKit с E2EE. Переписка и файлы не передаются через LiveKit.
6. Медиа шифруется на клиенте. Серверы и CI не получают пользовательские ключи расшифровки.
7. Доверенное устройство — основной путь подключения нового устройства, индивидуальный ключ восстановления — резервный.
8. Один активный аудиовызов на пользователя, одно аудиоустройство этого пользователя в конкретном вызове. Несколько устройств для переписки разрешены.

## Рабочие продуктовые допущения

Используем для последовательного проектирования; изменение не требует менять основной стек:

| Вопрос | Исходный вариант |
| --- | --- |
| Регистрация | Приглашение, подтверждённая почта, username, пароль; password reset через почту |
| Комната | Постоянный групповой чат с отдельными сеансами звонков |
| Права | Владелец, администратор, участник; приглашения и исключения — владелец/администратор |
| История для нового участника | Только после вступления; новое устройство существующего пользователя восстанавливает его доступную историю |
| Редактирование | Своё сообщение без начального временного ограничения, отметка «изменено» |
| Удаление | Своё сообщение для всех; администратор может удалить чужое; гарантии стирания чужих копий нет |
| Реакции и служебные сведения | Стандартные Matrix-реакции, typing, receipts доступны серверу как метаданные; требует явного согласования границ приватности до релиза |
| Файлы | Картинки до 10 МиБ, голосовое до 3 минут и 10 МиБ, серверный потолок загрузки с запасом на шифрование; настраиваемо |
| Темы | Светлая, тёмная и несколько акцентных палитр; выбор локальный для устройства |

Поддерживаемые версии Android/браузеров определяются ранним прототипом. Нельзя считать все браузеры, поддерживаемые Flutter, автоматически совместимыми с E2EE звонков. Поддержка iOS и видео остаётся за пределами v1.

## Порядок реализации

1. Проверить Flutter + Matrix E2EE, восстановление, отзыв устройства, локальное хранение и поиск.
2. Проверить P2P/TURN и LiveKit E2EE Android ↔ веб; оценить совместимость библиотек WebRTC.
3. Проверить пробуждение Android, гонку ответов с двух устройств, смену медиаключей и исключение участника.
4. Поднять воспроизводимый локальный Compose; добавить CI, резервирование и тестовое восстановление.
5. Реализовать пользовательские сценарии поверх проверенных адаптеров.

Это проверки осуществимости выбранного решения, а не уже выполненные тесты. Блокирующие риски и сценарии перечислены в [плане проверки](operations.md#проверка-архитектуры).
