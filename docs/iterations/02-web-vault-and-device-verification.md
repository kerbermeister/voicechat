# Итерация 2: веб-хранилище и проверка устройств

> Обновление: в [итерации 4](04-web-session-and-lavender.md) добавлено согласованное сохранение ключа в sessionStorage текущей вкладки. Описание хранения ключа только в памяти ниже относится к исходному строгому режиму без этой опции.

## Что меняется для пользователя

Веб-вход возвращён. Для каждого браузерного профиля нужна **отдельная локальная парольная фраза** (не пароль аккаунта), минимум 12 символов. Лучше длинная случайная фраза из менеджера паролей. При первом входе создаётся хранилище, при последующих фраза открывает существующее. Фраза не отправляется на сервер и не сохраняется в localStorage/IndexedDB. Смена пароля аккаунта её не меняет.

«Заблокировать» завершает звонок, останавливает клиент и закрывает доступ к ключу, сохраняя зашифрованную базу. После перезагрузки вкладки хранилище тоже нужно открыть заново. «Выйти» отзывает серверную сессию и удаляет локальную базу после подтверждения. Автоматического таймера блокировки пока нет.

Один профиль можно открыть только в одной вкладке одновременно. Разные профили/устройства работают независимо. Требуется HTTPS (для локального стенда допустим localhost) и браузер с Web Crypto, Web Locks и `indexedDB.databases()`.

Для общения нужно проверить устройства:

1. Открыть чат и нажать «Проверить устройства». Без выбранного чата показываются свои устройства.
2. На втором устройстве открыть тот же экран. Он показывает его собственные Matrix ID, device ID и полный отпечаток Ed25519.
3. Передать отпечаток лично или по независимому доверенному каналу. Ввести его для соответствующего устройства на первом экране.
4. Повторить проверку в обратную сторону. Не копировать «доказательство личности» из самого ещё не проверенного чата.

Это ручная сверка отпечатков, не SAS-эмодзи и не QR. Состояние доверия хранится локально в зашифрованной базе. Новое устройство требует новой сверки; восстановление recovery key не означает автоматического доверия всем устройствам собеседников. Несовпадение отпечатка не меняет доверие. Для текста и звонков используется `ShareKeysWith.directlyVerifiedOnly`; непроверенные устройства блокируют отправку/подключение, а не получают ключи молча. Появление нового непроверенного устройства завершает текущий звонок по правилам предыдущей итерации.

## Устройство vault

`web/vault.js` использует только браузерный Web Crypto: PBKDF2-HMAC-SHA-256, 600 000 итераций, случайную соль 16 байт и неэкспортируемый AES-GCM-256 CryptoKey. Каждая запись получает случайный nonce 12 байт; профиль, имя object store, ключ записи и версия формата входят в authenticated additional data. Перестановка зашифрованных значений между записями отклоняется.

В `${profile}.vault` находятся версия, соль и зашифрованная проверочная строка. В `${profile}.encrypted` — Matrix-база с зашифрованными значениями. Названия таблиц, ключи записей, размеры и количество записей не скрыты. Это защита токенов, секретных ключей и содержания истории, не сокрытие всех метаданных.

SDK 14.2.0 не предоставляет шифрующего codec для IndexedDB. Зафиксирован небольшой патч поверх исходников SDK: [происхождение и описание](../../vendor/matrix/VOICECHAT_PATCH.md). Шифрование завершается до открытия write-транзакции IndexedDB; чтение аутентифицируется до попадания в SDK. Открытые значения кэшируются только в памяти. Ошибка аутентификации записи не должна запускать автоматическое удаление истории SDK. Алгоритмы Olm/Megolm не изменялись.

Web Locks исключает конкурирующую запись двух вкладок. Неверная фраза, неизвестный формат, утраченный заголовок существующей базы и неподдерживаемый браузер закрывают доступ без перехода на plaintext.

## Обновление и восстановление

Старые незашифрованные IndexedDB-профили прототипа не открываются и не удаляются автоматически. Сначала проверить резервную копию и recovery key на другом устройстве. После этого можно удалить старые тестовые данные сайта и войти заново. Создание другого профиля не стирает старую незашифрованную историю.

Если локальная фраза забыта, recovery key не открывает этот файл: он восстанавливает историю из серверной E2EE-копии в новом профиле. Потерянную серверную сессию следует отозвать с другого устройства. Перед удалением данных сайта учитывать, что браузер удаляет все профили этого origin.

## Границы защиты

Vault защищает данные на диске в заблокированном состоянии. Он не защищает от XSS, вредоносного обновления сайта, расширения с доступом к странице или захваченного разблокированного браузера. Неэкспортируемость CryptoKey не запрещает коду origin выполнять расшифровку в открытой сессии. В среде с GC нет гарантированного физического обнуления всех копий памяти. AEAD обнаруживает изменение записи, но не откат целого хранилища к ранее валидной копии.

Ручная проверка зависит от правильного выбора человека, устройства и независимого канала сверки. Удаление устройства не стирает уже полученные сообщения. Серверный отзыв LiveKit/смена эпох, HTTPS-деплой и независимая проверка безопасности остаются обязательными работами до выпуска.

## Проверки и запуск

Обычные сборки используют `lib/main.dart`; лабораторные скомпилированные пароли не распространять. Полный сценарий: [prototype/README.md](../../prototype/README.md).

```sh
cd apps/client
flutter pub get --enforce-lockfile
flutter analyze
flutter test
flutter test integration_test/storage_test.dart -d emulator-5554
cd ../..
python3 -m unittest discover -s prototype -p 'test_*.py'
# После web build и запуска serve_web.py; Playwright доступен в NODE_PATH:
node prototype/test_web_vault.cjs
```

Браузерный тест проверяет шифрование, неверную фразу, подмену ciphertext, привязку к записи, блокировку, перезагрузку, конкурирующие вкладки и удаление. Лаборатория проверяет дополнительно Matrix round-trip через vault, отказ непроверенному устройству/неверному отпечатку, сохранение доверия после повторного открытия, Android ↔ web, восстановление истории и групповые звонки с отзывом.

- Прогон `1792585304`: Android ↔ web, восстановление двух сообщений новым устройством при отключённых старых клиентах, сохранение доверия, расшифровка аудио каждым из трёх участников и отзыв доступа — PASS. [Этапы без секретов](../../prototype/verified-web-vault-run.json).
