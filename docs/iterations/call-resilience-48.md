# Устойчивость звонков: кандидат 1.19.0+48

Дата: 02.11.2026. Исходная production baseline: 1.18.0+47,
`2254b1d0b5500f576b9366d7376799101eb5d71e`. Требования и пользовательская
приёмка ведутся только в [едином реестре](../user-acceptance.md).

## Найденные причины и границы вывода

- Системный picker мог оставаться открытым 60 с, а screen lease жил 30 с.
  `_acting` подавлял heartbeat; клиент закрывался после 25 с без авторизации.
  Истечение direct lease было terminal до следующего звонка. Теперь heartbeat
  работает во время picker, временное истечение отзывает все старые leases и
  поколение, требует новых взаимных подтверждений пары. Explicit leave, отзыв
  ключей/участия и server recovery остаются terminal. Это воспроизводимый дефект
  кода; точный путь на удалённом Xiaomi по отсутствующим логам не установлен.
- Web SDK создавал независимые элементы для аудио и видео и новые Dart-обёртки
  треков при каждом чтении. Сравнение обёрток повторно привязывало тот же источник.
  Web renderer сохраняет исходный комбинированный поток, сравнивает ID треков;
  native сохраняет сравнение объектов и явный trackId из исправления47.
- `element.volume` не обеспечивает нужную регулировку на iOS. Реальная проба
  также обнаружила тишину при MediaElementAudioSource для WebRTC srcObject.
  MediaStreamAudioSource + GainNode работает на всём диапазоне; графы очищаются
  при замене источника и исключают дубли при переходах audio/video/LiveKit.
- RTT учитывал также невыбранные старые ICE-пары. Теперь используется текущая
  выбранная пара; ухудшение подтверждается двумя измерениями, восстановление
  тремя. В режиме авто меняются параметры отправителя без перезапуска камеры.
- Failed транспорта немедленно завершал звонок до попытки восстановления ICE.
  Теперь действует прежний ограниченный срок 15 с; дубли событий объединяются,
  позднее обновление TURN не перезапускает уже восстановленный peer.

## Браузерные проверки

Внутренний браузер Chromium156 на Mac, синтетические локальные WebRTC peers,
без аккаунтов, отправки звука наружу, записи экрана или сохранения кадров:

- Реальный RMS выходного аудиосигнала: 100%=0.07097, 50%=0.03542, 0%=0,
  200%=0.14064. Уровни задаёт production `media_audio.js`; аппаратный выход
  в пробе заглушён. Это не прослушивание физического iPhone.
- Production web renderer: единый A/V srcObject, скрытый SDK audio заглушён,
  видео продолжает двигаться после остановки передачи на 2 с, изменения
  разрешения 320→640 и ICE restart. Это не измерение губ/звука у двух людей.
- 10 Node-проверок: выбор аудиовыхода через AudioContext либо generated stream,
  отказ выбора сохраняет действующий путь, неверный sink не принимается;
  независимые уровни участников, 0% до усиления, удаление/замена графа,
  отсутствие удвоения при включении/выключении видео.

Последние60 сырых измерений сохраняются только в памяти текущего личного звонка
и доступны в существующей диагностике, в том числе сразу после завершения:
относительное время, loss/jitter/RTT выбранной пары, причины оценки, разрешённые
значения ограничения encoder CPU/bandwidth. Сырые скачки не скрываются сглаживанием.
Точные сетевые метрики прошлого пользовательского эпизода отсутствуют: две ошибки
оценки воспроизведены тестами, но приписать им именно тот эпизод пока нельзя.

## Платформенные ограничения

Вывод выбирается только из реально предоставленных браузером устройств:
AudioContext.setSinkId, иначе HTMLMediaElement.setSinkId для generated stream.
Успешный readback sink ID не доказывает акустический маршрут iPhone. Обязательная
физическая проверка Safari и PWA остаётся открытой в UA-09.C13.

Источники платформенных решений: [WebRTC media streams](https://webrtc.org/getting-started/remote-streams),
[WebKit: getDisplayMedia на iOS](https://bugs.webkit.org/show_bug.cgi?id=231455),
[WebKit: вывод single-track WebRTC](https://bugs.webkit.org/show_bug.cgi?id=320086),
[WebKit: MediaStreamAudioSource](https://bugs.webkit.org/show_bug.cgi?id=230902).
Не обещается отправка экрана или выбор разговорного динамика при отсутствии
соответствующего API браузера; отдельный нативный iOS-клиент этим выпуском не создаётся.

## Локальные проверки перед выпуском

- Python:839 PASS,3 штатных пропуска. Flutter:556 PASS,4 штатных пропуска,
  затем8 адресных тестов после добавления диагностики и12 проверок capture
  (включая Android первый кадр/отсутствие кадров и очистку сервиса). Analyzer чист.
- Реальный native macOS WebRTC:1 PASS, три цикла звонка — два приёма с RTP и
  DTLS и отмена до ответа, правильное завершение на втором peer. Сигналинг
  локальный, это не проверка внешнего TURN или аппаратного lip-sync.
- Android API35 integration собран и установлен в отдельный тестовый эмулятор,
  но **не пройден**: системный MediaProjectionPermissionActivity остался без
  подтверждения, тест завершился timeout5мин. Доступный инструмент UI не смог
  подключиться к standalone Qt-окну эмулятора; разрешение не обходилось. Это
  не свидетельство получения кадров. Физический Xiaomi также недоступен.
- Резервная копия Mac47 и профиля проверена по хешам:285 файлов/ссылок приложения,
  321 элемент профиля. Keychain не удалялся и не изменялся для обновления.

Кандидат. Публикация, подписи, обновление установленного Mac и проверка
