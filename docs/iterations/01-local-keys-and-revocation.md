# Итерация 1: локальные ключи и отзыв устройств

Дата: 2026-10-21. Это первый шаг от лаборатории к MVP, не разрешение использовать приложение для чувствительных данных.

## Реализовано

- Android: вся база Matrix, включая токен, Olm/Megolm, кэш восстановления и сообщения, хранится в SQLCipher. Случайный 256-битный пароль базы хранит `flutter_secure_storage` с защитой Android Keystore. Одного `MatrixSdkDatabase.secureStorage` недостаточно: SDK 14.2.0 сохраняет эти данные также в основной базе.
- Автоматический сброс ключей отключён. При отсутствии ключа существующая база не перезаписывается. Перед открытием существующего файла для записи выполняется чтение с ключом в read-only режиме: стандартный Android SQLite opener может пересоздать файл, который считает повреждённым.
- Android не допускает системные скриншоты/превью экрана; резервное копирование данных приложения отключено. Это не защита от root, вредоносного кода в процессе или фотографии экрана. Биометрическая блокировка приложения пока не реализована.
- Экран «Устройства» показывает сессии аккаунта и позволяет отозвать другую сессию с повторным вводом пароля. Пароль используется только на время операции. Текущая сессия закрывается отдельной кнопкой выхода; после успешного серверного logout удаляются её локальный ключ и база. Ошибка запроса выхода не очищает локальную историю (поведение `Client.logout` SDK обойдено через его API).
- Перед отправкой текста сервер заново подтверждает токен, участников и устройства; ошибка проверки блокирует отправку. Каждый новый текст использует новую Megolm-сессию, поскольку SDK не гарантирует ротацию при удалении устройства. Для нескольких десятков пользователей это сознательная плата за простую реализацию.
- Звонок проверяет тот же список доступа каждые 3 секунды с таймаутом проверки 5 секунд. Изменение списка устройств/ключей/участников или ошибка проверки завершает звонок. Продолжение требует нового звонка с новыми ключами. Бесшовная смена ключей не реализована.
- Удалённые подключения требуют HTTPS/WSS; HTTP/WS разрешены только для loopback-стенда. Используется явно заданный Matrix URL без well-known переадресации.

## Веб и старые данные

Обычная веб-сборка отключает вход и не открывает Matrix IndexedDB: защищённого браузерного vault пока нет. Исключение явно задано только в `lib/lab_main.dart` для одноразовых тестовых аккаунтов. Это ограничение текущей итерации, а не отказ от веб-версии продукта.

Существующие незашифрованные Android-профили `.db` не мигрируются и не удаляются автоматически. Вход в такой профиль блокируется. До очистки данных приложения нужно в предыдущей версии сохранить recovery key, выгрузить резервную копию ключей и проверить восстановление истории на другом устройстве. Затем можно очистить тестовые данные приложения, войти заново и восстановить историю. Не считать выбор другого имени профиля удалением старой незашифрованной базы. Без проверенного восстановления данные не очищать.

При потере Keystore-ключа локальную базу открыть нельзя: требуется восстановление через recovery key/другое устройство. Приложение не заменяет отсутствующий ключ новым поверх существующего файла.

## Что означает отзыв

Сервер Matrix отклоняет старый токен; локальный издатель токенов звонков тоже отказывает ему. Новые сообщения не используют прежний ключ Megolm. Остальные обновлённые клиенты прекращают активный звонок после обнаружения изменения доступа.

Отзыв не стирает уже скопированные сообщения и ключи. Если злоумышленник получил recovery key или ключи подписи личности, одного удаления устройства недостаточно: потребуется отдельный процесс смены личности/резервной копии. Он не входит в эту итерацию.

Проверка доступа и отправка не являются атомарной серверной операцией. Ожидаемое окно обнаружения в активном клиенте — интервал 3 с плюс таймаут 5 с; это не гарантия реального времени при приостановке процесса. Ранее выданный JWT LiveKit ещё может позволять транспортное подключение до истечения срока; принудительный server-side disconnect/эпохи доступа остаются следующей работой. Уже выданный медиаключ не исчезает у получателя, поэтому текущие отправители останавливаются вместо продолжения со старым ключом.

## Проверка

`apps/client/integration_test/storage_test.dart` на Android проверяет отсутствие открытого токена/SQLite-заголовка в файле, невозможность чтения без ключа и с неверным ключом, повторное открытие с правильным ключом, сохранность базы при неверном/утерянном Keystore-значении и сохранность старого plaintext-профиля. Негативное чтение выполняется read-only на копии.

```sh
cd apps/client
flutter test integration_test/storage_test.dart -d emulator-5554
flutter analyze
flutter test
cd ../..
python3 -m unittest discover -s prototype -p 'test_*.py'
```

Сквозной сценарий из `prototype/README.md` дополнительно проверяет неверный пароль отзыва без удаления устройства, HTTP 401 для отозванного токена Matrix и выдачи JWT, завершение звонков у трёх клиентов, новую Megolm-сессию и отказ расшифровки нового текста сохранённым старым ключом. Действующие Android/web-участники должны получить этот текст.

Результат 2026-10-21: **PASS** на эмуляторе Android 35 ARM64 и двух отдельных вкладках Chrome с синтетическим звуком. [Санитизированный журнал](../../prototype/verified-security-run.json) не содержит токенов, паролей и ключей. Пройдены SQLCipher/Keystore integration test, 6 Flutter-тестов, анализатор и 3 Python-теста. Это локальные проверки, не результат GitHub Actions и не аудит криптографии.
