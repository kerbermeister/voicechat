# Ручное обновление Android — 25 октября 2026

Реализован локальный кандидат **1.1.0 (сборка 2)**. Обычный подписанный APK
собран из `lib/main.dart`; публикация на VPS и запуск нового GitHub workflow
не выполнялись. План остаётся открытым по внешним условиям выпуска.

## Поведение

«О приложении» доступно из настроек и экрана входа. Версия читается из установленного
Android-пакета, на web используется проверяемое значение из pubspec. Только
«Проверить обновления» обращается к серверу. Новая версия показывает размер и
описание; «Скачать и установить» разрешает загрузку. После выдачи разрешения
Android требуется «Продолжить установку», а затем системное подтверждение.
Нет фонового поиска обновлений, push, автозагрузки или тихой установки.

Проверяются HTTPS origin, схема и дубликаты JSON-полей, размер/границы потока,
SHA-256, package, versionName/versionCode, minSdk и сертификат. Android окончательно
проверяет подпись устанавливаемого файла. Нативный обработчик хеширует и те байты,
которые записывает в PackageInstaller session. Redirect и сторонний URL запрещены.
Отмена/ошибка не очищают профиль, БД или Keystore. Временные файлы изолированы;
после гибели процесса осиротевшие APK очищаются, незавершённая session сверяется.

Черновики текста теперь сохраняются через существующую зашифрованную БД под
локальным ключом `dev.voicechat.local.drafts`, недоступным для перезаписи серверным
account data. Перед установкой ожидается завершение записи. Звонок, запись,
активная отправка, несохранённые вложения, ответ/редактирование блокируют установку.
Формат существующей SQLCipher-БД и имена ключей не менялись.

## Выпуск

- Версии и notes сверяются между pubspec, `app_version.dart`, историей и APK.
- Release Gradle требует отдельный ключ; debug fallback удалён. Исправлена
  прежняя ошибка release-lint в loopback network security config.
- `.github/workflows/android-release.yml`: ручная сборка кандидата, отдельная
  публикация сохранённого артефакта из `source_run`, без повторной компиляции.
- Публикация требует точных `ANDROID_ACCEPTED_BUILD` и `ANDROID_ACCEPTED_SHA256`,
  проверяет исходный commit, подпись, метаданные и конфликт тега.
- APK размещается в постоянном каталоге, Caddy монтирует его read-only.
  Публикации сериализуются `flock`; публичный APK проверяется до атомарной смены
  manifest. Сохраняются предыдущий manifest и неизменяемые старые APK.
- Отзыв возвращает предыдущий manifest; если его нет, отключает канал. На телефоне
  downgrade не выполняется. Следующее исправление получает новый номер.

[Команды, secrets и настройки](../../infra/README.md#ручные-android-обновления).
Первое внедрение требует **full**-релиза инфраструктуры из-за Compose/workflow.
Новая production baseline не создавалась и её файлы не менялись вручную.

отсутствие загрузки до согласия, отсутствие сетевой проверки на старте/возврате,

Эмулятор использовал **отдельный AVD** и
`integration_test/apk_update_fixture.dart`, версии 9.0.0+100 и 9.0.1+101.
Это тестовые номера, они не входят в историю production-выпусков. Созданы
синтетические user/device/token, криптографическая идентичность vodozemac и
Megolm-сессия; данные сохранены через настоящие SQLCipher и Keystore.
После системного обновления и перезагрузки сравнивались идентификаторы,
публичный отпечаток, hash ключа БД, черновик и 4096 байт blob; сохранённый
ciphertext успешно расшифрован прежней Megolm-сессией.
[Машиночитаемый результат](../../prototype/verified-android-update-run.json).

HTTP transport fixture перенаправляет фиксированный тестовый origin на loopback
через `adb reverse`; он не включён в обычный APK. Этот результат не является
проверкой production TLS, живого Matrix-аккаунта, его backup/доверия/очереди через
сервер или E2EE-медиазвонка. Нижние API Android (включая API 24) ещё требуют прогона.

## Что остаётся перед выпуском

1. Проверить на физическом Android реальный профиль, старую/новую личную и групповую
   переписку и E2EE-файл, доверие устройства, очередь и отрицательные сценарии из
   AU-07. Дополнить матрицу поддерживаемых Android API и устройств.
2. Сохранить внешнюю копию release-ключа; настроить GitHub secrets/variables,
   закоммитить и доставить revision. В текущем checkout Git remote не настроен.
3. Штатно развернуть инфраструктуру `full`, проверить постоянный mount/route,
   затем получить и принять кандидат в CI, опубликовать его точные байты и
   проверить public manifest/digests/rollback pointer. Для полного VPS-релиза
   дополнительно действуют существующие backup и healthcheck.

Функция реализована и проверена локально. Полную производственную готовность
до этих внешних шагов документ не заявляет.
