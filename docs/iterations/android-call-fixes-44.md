## Видео Android

Совместимая пара `flutter_webrtc1.6.3` / `livekit_client2.13.2` включает
[исправление владения удалёнными tracks](https://github.com/flutter-webrtc/flutter-webrtc/pull/2230).
Старый Unified Plan callback не регистрировал track. Renderer мог получить
обёртку из `getTransceivers`, которую следующий запрос освобождал вместе с sink.
Декодер продолжал работать, но отображение останавливалось.

Одинаковый нативный Android15/API35 fixture на старой паре1.6.2+hotfix.4/2.13.1
оставляет renderer480×270 при уже декодируемом320×180 и завершается ошибкой.
Новая пара обновляет отображение и проходит два повторных включения камеры.
В fixture wire track IDs отличаются от локальных IDs второго peer: иначе
общий native registry двух peers одного процесса может привязать локальную
камеру вместо удалённой и сделать сравнение недостоверным.
[A/B](release-44/android-video-sdk-comparison.json),
[итоговый прогон](release-44/android-media-final.json).

Исправлен также контракт `Helper.switchCamera`: возвращаемый bool обозначает
переднюю камеру, а false — успешное переключение на заднюю; ошибки выбрасываются.

Это синтетическая сигнализация и VP8 на эмуляторе, без Matrix-авторизации,
проверки E2EE медиапотока и аппаратного H264 Xiaomi12S. В teardown библиотеки
остаётся перехваченный `streamDispose/ConcurrentModificationException`;
после прогона native camera clients пусты и обе камеры отключены. Этот warning
не выдан за причину первоначального зависания или доказанную утечку камеры.

## Голос и счётчик

Новые голосовые:16/24/48кГц, по умолчанию24кГц; выбор сохраняется на устройстве.
Частота фиксируется при старте записи. PCM16/mono, WAV и предел180s сохранены;
запись остаётся в памяти. Android API реально выдал данные во всех трёх режимах.
Web recorder использует существующий resampler, формирующий выбранную частоту.
Это частота дискретизации, а не битрейт Opus; сравнение качества с Telegram
субъективно не выполнено. Для записи запрошено шумоподавление; прямые звонки
запрашивают mono48кГц/AGC вместе с прежними echo cancellation/noise suppression.
Возможность и результат обработки зависят от платформы.

Максимум48кГц/180s —17,280,044байта с WAV header; повышен только лимит аудио.
Старый клиент ограничен10MiB и не загрузит длинную запись48кГц свыше этого
размера.24кГц/180s —8.64МБ и укладывается в прежний лимит. Старые16кГц WAV
сохраняют правильные частоту и длительность при воспроизведении.

Локальная коррекция unread исключает скрытые call-сигналы только при полном
расшифрованном интервале. При разрыве кеша, ещё не пришедших событиях или
нерасшифрованном содержимом сохраняется серверный счётчик. Read receipts и
серверные значения не меняются. Шесть тестов включают muted chat, count-only
sync и реальный виджет списка.
