# Мобильные звонки и сообщения: MC-11–MC-22

Кандидат 1.5.0+7. Не объявлять итерацию принятой до публикации и аппаратной проверки.

## Реализация

- MC-11/12: мобильное окно fullscreen с safe areas, входящий вызов с вертикальной
  иерархией; активное видео занимает основную область, controls снизу. ScreenPanel
  не уменьшает обычное видео, если показа нет; активный экран виден в звонке.
- MC-13: общий roomDisplayName вместо технического room name; нейтральный fallback
  подписи видео без device ID.
- MC-14: отдельная кнопка экрана, runtime feature detection getDisplayMedia.
  Обход только устаревшей mobile-UA проверки LiveKit, E2EE/допуски/согласие ОС
  не меняются. Android native использует прежний MediaProjection flow.
- MC-15: короткий собственный сигнал ended.wav, одно завершение — один сигнал,
  выключенные звуки не воспроизводят его после повторного включения.
- MC-16: центрирование кружка/подписей, прозрачная область вне круглого видео.
- MC-17: Matrix 14.2 не публикует decryptedTimelineQueue в onTimelineEvent;
  отдельная подписка принимает позднюю расшифровку, но не историю. Защита от
  позднего invite после end. Это найденный дефект, не доказанное воспроизведение
  исходного сбоя между двумя iPhone.
- MC-18: encrypted to-device состояние своего аккаунта; sender key сверяется с
  разрешённым собственным устройством, room/session проверяются, временные границы
  и порядок защищены. Принятие отправляется после успешного answer/connect,
  heartbeat каждые 20 секунд, статус истекает через 60. Конец не прерывает
  разговор другого устройства, сторонние участники группы не получают этот сигнал.
- MC-19: короткий tap переключает режим, hold запускает запись; свайп отменяет
  видеокружок. Кнопки остановки/отмены и доступное управление сохранены.
- MC-20: web recording больше не открывает пробный getUserMedia до записи.
  Звонки используют запрос медиа SDK; отказ в доступе не обходится, неактивный
  микрофон не удерживается ради разрешения.
- MC-21: long press + существующие dots/right click, общие действия и иконки.
  На touch сообщение не конфликтует с системным выделением; есть «Скопировать».
- MC-22: навигация после подтверждения outbox, ошибки остаются в исходном чате,
  повтор ожидания использует тот же transaction. Текст и вложения исходного
  черновика сохраняются при таком переходе в рамках открытой сессии.

## Ограничения и аппаратная приёмка

Нужно проверить iPhone 11 Pro/iOS 27.0.1: оба направления личного/группового
звонка, холодный запуск, позднее приглашение, ответ на телефоне при открытом Mac
и браузере, исчезновение ringtone и статус с именем; screen picker, реальные
кадры/остановку/отмену; запись и долгое нажатие, narrow/landscape/large text.
Фоновую/закрытую PWA нельзя приравнивать к открытому приложению без проверки push.

Постоянное разрешение PWA после холодного запуска зависит от WebKit:
[WebKit 327237](https://bugs.webkit.org/show_bug.cgi?id=327237),
[WebKit 280394](https://bugs.webkit.org/show_bug.cgi?id=280394).
Они описывают повторные запросы; не доказано совпадение с конкретной iOS пользователя.
Наличие getDisplayMedia проверяется динамически; сообщения о поддержке iOS 27
не заменяют физическую приёмку: [BCD 30654](https://github.com/mdn/browser-compat-data/issues/30654).

Глобальный handoff и Windows native adapter остаются отдельными будущими задачами.
