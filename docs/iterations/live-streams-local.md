## Реализованная изолированная часть

`prototype/stream_sessions.py`: серверное ядро без подключения к production API.
Один эфир/пользователь; десять зрителей и одно устройство просмотра/аккаунт;
атомарный допуск; проверка выбранной аудитории; отдельные live/paused/reconnecting;
ручное resume, 60-секундный timeout обычного обрыва и фиксированный deadline.
История непрозрачных ciphertext-конвертов только в RAM, sequence/snapshot,
повторная отправка без дублей, ограничения размера/частоты и общего числа сообщений.
На диске только opaque поколения для последующего SFU cleanup.
После restart сессии/история не возвращаются, поколения ждут подтверждения удаления.
Повтор start с тем же request ID не создаёт второй эфир, а после stop не запускает
новый в ограниченном окне повторов; replay-cache ограничен по размеру и времени.

`prototype/stream_protocol.py`: строгая граница JSON v1 и dispatch метаданных/чата.
Повторные/лишние поля, неподдержанные операции, NaN, неверные revision, неканонический
base64 и oversized envelope отклоняются. Actor задаётся доверенным адаптером,
клиент не может прислать owner/role. Здесь намеренно нет операции выдачи SFU grants.
Это ещё не HTTP endpoint или законченное API стримов.

## Ранняя инвентаризация и оставшиеся зависимости

ADB не обнаружил подключённого Android; xctrace перечисляет физический iPhone,
но управление им/разрешениями/принятием системного звонка не выполнено.
Сам факт перечисления iPhone не считается проверкой Safari/PWA.

`call_probe.dart` (`shareKey`, `_shareKey`, `_receive`) привязан к Matrix room,
актуальному roster/поколению и выдаёт короткоживущий ключ повторно от ведущего.
`screen_key.dart` принимает только active snapshot. Прямой перенос в стрим
не решает поздний вход во время паузы владельца и доступ к историческим эпохам.
Нужна отдельная проба протокола конвертов/ephemeral key delivery до подключения API.
В просмотренных Flutter-путях не найден готовый обработчик системного interruption,
который обеспечивал бы согласованную паузу iPhone web/PWA. Нельзя выдавать
60-секундное завершение за её реализацию.

Поэтому G1 не закрыт; T02 подготовлен только как неактивный изолированный модуль,
чтобы проверить независимые алгоритмы. HTTP/auth/device grants, real SFU cleanup,
ключи, UI, медиа, конфигурация запуска, клиентские/аппаратные проверки и выпуски
не реализованы этой итерацией. Режим «локально» сохраняется и для следующих шагов;
публикация требует отдельного разрешения владельца, несмотря на общий release-план.
