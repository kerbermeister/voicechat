# Повторный вызов и отказ захвата macOS — кандидат34

Рабочая база — опубликованный source5b3f08c, отчёты main d588b95.
Изменения только apps/client и docs: production web-only допустим при штатной
проверке baseline; общий Dart затрагивает также Mac и Android.

31.10 пользователь уточнил: личный вызов, после разговора повторный без ответа,
нажатие красной кнопки не остановило гудок. Найдены зависимость остановки звука
от незавершённого play и starting, не сбрасываемый при отмене. Отмена теперь
публикует терминальное состояние до cleanup/network; поздние операции старта
проверяют поколение и не присваивают active после отмены. Пока SDK завершает
старый запуск, новый запуск сериализован. Звук имеет ревизию: stop прерывает
pending play немедленно и повторяется после запоздавшего завершения playback.

Системный журнал реального установленного Mac33: несколько отказов
ScreenCaptureKit SCStreamErrorDomain -3801 (TCC denied). В System Settings
Screen & System Audio Recording переключатель VoiceChat включён. codesign
показывает ad-hoc designated requirement по cdhash. Это подтверждённый отказ ОС
при визуально включённом разрешении; новая подпись — вероятное объяснение.
SDK flutter_webrtc логирует ошибку SCK, но всё равно возвращает live track.
Теперь штатный Helper.requestCapturePermission проверяет разрешение до захвата;
локальный renderer ждёт первый кадр8s до публикации/claim. При ошибке или отсутствии
кадра track/stream/renderer освобождаются. Чёрная трансляция вместо ошибки не
объявляется начатой. Доступ TCC/Keychain не обходится и не сбрасывается командой.

iPhone web: клиент проверяет наличие getDisplayMedia, а не user agent.
Отсутствующий API нельзя заменить выдачей разрешения в веб-клиенте; просмотр
сохраняется. Новое нативное iOS-приложение/ReplayKit extension в эту правку не входит.
Открытие внешней документации MDN было отклонено браузером; текущая внешняя
матрица поддержки не проверена.
