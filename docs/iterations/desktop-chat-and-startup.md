## Drag and drop

Desktop web принимает несколько файлов в границах открытого чата; файловый drop
не открывает файл вместо страницы. Действие блокируется на время другой операции.
JPEG/PNG/WebP/BMP проходят прежнюю валидацию и сжатие; GIF, неподдерживаемые форматы
изображений, видео, аудио и документы используют обычный файловый путь. Большие
файлы читаются частями. Если браузер не сообщил MIME, известные расширения дают
тип; фотографии всё равно проверяются декодером. Папки не поддерживаются.

Смешанные фото и файлы остаются черновиком до отправки; альбом отправляется
первым с подписью. При последующей ошибке файла готовый альбом не отправляется
повторно. Сохранены ограничения политики и E2EE. Native macOS drag and drop
не добавлен; эта реализация относится к браузеру на компьютере.

## Демонстрация экрана — частичное исправление

У получателя добавлен срок ожидания защищённого изображения — 20 секунд.
Повторяющиеся события не продлевают его. Ошибка различает отсутствие ключа,
видеотрека и успешной расшифровки. Можно переподключить только экранную room,
не заканчивая основной звонок. Успешное получение убирает ошибку. Событие E2EE
проверяется также по допустимой публикации; проверки ключей/допуска не ослаблены.

Это устраняет бесконечное ожидание в попытке получения, но **не доказывает
исправление исходного чёрного экрана**. Браузер/ОС получателя неизвестны.
Нужен реальный звонок MacBook Chrome → второй компьютер и диагностика обеих
сторон. Нового подтверждения декодированных кадров в этой итерации нет.

## iPhone webapp — оптимизация, приёмка открыта

Пользователь уточнил: iPhone 11 Pro, iOS 27.0.1. Примерно 25 секунд после полного
закрытия webapp при почти мгновенном открытии в Safari и на компьютере.
Xcode видит физический iPhone offline; эмулятор не использован как замена приёмке.

После Flutter build release workflow запускает `tool/version_web_assets.py`:
main.dart.js и дерево CanvasKit копируются под общий SHA-256 URL. Изменение
любого содержимого меняет URL. Bootstrap и preload ссылаются на этот URL.
Caddy выдаёт существующим versioned ресурсам годовой immutable-кеш; HTML,
bootstrap и остальные постоянные пути сохраняют no-cache. Пропущенный
versioned ресурс возвращает 404 без SPA fallback и без immutable-кеша.
Пользовательское хранилище, сессии и ключи не очищаются.

Это убирает обязательную сетевую перепроверку кешированных крупных ресурсов.
Первая загрузка и вытесненный браузером кеш по-прежнему требуют скачивания;
причина исходных 25 секунд и выигрыш на iPhone пока не подтверждены.
`performance.getEntriesByType('mark')` содержит только этапы
`voicechat-shell`, `voicechat-entrypoint`, `voicechat-engine`,
`voicechat-run-app`, `voicechat-first-frame`, без пользовательских данных.
Для приёмки нужны повторные замеры webapp/Safari на одном iPhone и одной сети,
с полным закрытием приложения, без очистки хранилища.
