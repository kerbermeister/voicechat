## Реализация

- Превью ответа использует собственный текст непосредственного адресата, скрывая
  Matrix fallback прежней цитаты; переход сохраняет исходный event_id.
- Закрепления — стандартное состояние Matrix `m.room.pinned_events`, права комнаты,
  панель перехода. Истёкший текст скрывается у всех; клиент с правами закрепления
  сохраняет очищенный список при открытии/обновлении чата. Серверного обхода всех
  комнат нет. Автоматическая проверка отклонила такой первоначальный вариант
  из-за широкой мутации общего состояния; он не применялся.
- Композер на desktop восстанавливает фокус, уважает поиск, модальные окна,
  выделение и Tab. На телефоне область принимает аппаратный ввод, не открывая
  экранную клавиатуру при обычном входе; первая буква перенаправляется в поле.
- Статистика реакций хранится локально в зашифрованной БД конкретного аккаунта,
  учитывает подтверждения и transaction_id, ранжирует12. Полоса показывает6 ячеек
  и прокручивается. Выбор emoji анимирован одним контроллером, reduced motion
  соблюдается, отправленные emoji статичны. Размер увеличен примерно на20%.
  Для красного сердца явно используется системный цветной emoji-шрифт: Inter
  содержит собственный одноцветный glyph. Новые удалённые ассеты не загружаются.
- Начало звонка окрашено тематическим зелёным, завершение — цветом ошибки темы.
  `~~текст~~` разбирается существующим markdown-пакетом только как inline strike;
  HTML остаётся текстом, ссылки и исходные маркеры редактирования сохраняются.
- Фото/видео используют общий прозрачный modal backdrop с размытием чата.
  Строка человека/группы подсвечена до закрытия её меню.
- Выбор нескольких сообщений заменяет композер панелью удаления/пересылки,
  сохраняет черновик, проверяет права, исключает недоступные сообщения.
  Успехи частичной операции снимаются с выбора; повтор использует прежний txid.
- «Исчезнуть после прочтения» разрешено только в личном E2EE-чате;5с по умолчанию,
  есть явный выбор. Несовместимые режимы таймеров взаимно отключаются. Отдельные
  появление/стирание, маскированные цитаты и контроль закреплений.
- Аудио:1/1,25/1,5/1,75/2× без перезапуска источника; Darwin использует
  `AVAudioTimePitchAlgorithm.timeDomain` для сохранения высоты голоса.
- Любой тип исходящего сообщения получает карточку до завершения локальной
  записи; сеть запускается только после её успешного завершения. При отказе диска
  карточка откатывается, черновик сохраняется. Большие файлы предварительно
  копируются/шифруются локально: освобождение черновика не опережает сохранение
  вложения. Сетевая отправка идёт в фоне; загрузка частей показывает реальный
  процент подтверждённых байтов. Внутри чата сохраняется порядок очереди.
  Подтверждённая карточка живёт до echo в timeline; raw bytes не удерживаются
  в этом небольшом временном списке. Ошибка заменяет spinner красным «!»;
  нажатие открывает безопасную причину, рекомендацию и повтор. Сырые исключения,
  URL, серверные тела и токены не сохраняются в описании ошибки.

## Серверный контракт и интеграция

`POST /_synapse/client/voicechat-read-after` использует обычный Matrix Bearer token,
проверяет актуальное участие в приватном DM и его marker. Доступен только
получателю для запуска; отправитель может запросить состояние. Содержимого
переписки в запросе/ответе нет. Списки состояния ограничены100 event_id, клиент
разбивает большую загруженную историю на пакеты.

Первое чтение атомарно создаёт строку в штатной таблице Synapse `event_expiry`.
Повтор не продлевает срок; клиентский read_at ограничен временем исходного
сообщения и текущими серверными часами. Перед вставкой проверяется persisted
content, чтобы конкурентное уничтожение не могло запустить таймер повторно.
Штатный scheduler удаляет ciphertext и восстанавливает расписание после рестарта.
Новая схема БД не вводится. Использованы внутренние API **закреплённого** Synapse:
при смене его версии этот реальный тест обязательно повторить.

Клиент сохраняет неподтверждённое чтение локально, скрывает сообщение по
монотонному grace timer; после перезапуска ранее прочитанная неподтверждённая
копия скрыта до сверки сервера. Офлайн-подтверждение отправляется при соединении.
Сервер не может узнать о первом чтении полностью офлайн до восстановления сети;
локально содержимое скрывается своевременно. Прежние копии/скриншоты и backups
не обещано уничтожать.

Это изменение клиентского Flutter-кода, Matrix vendor и Synapse policy; после
согласования общего revision потребуется штатный **full**-релиз, затем macOS
через существующий `--personal`/Sparkle канал. Текущая установленная версия не
менялась. Перед сборкой релиза заново сравнить общую интегрированную ветку с
актуальным production manifest, включая изменения другого агента. Не переносить
из этой ветки инфраструктурные решения: их здесь нет.
