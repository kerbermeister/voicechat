## Подготовка и отмена

В53 реальный CallController удерживал Future запуска после отмены, если
подготовка платформы не завершилась. Уже зарегистрированная исходящая SDK-сессия
при этом могла не принадлежать кнопке отбоя. Две регрессии воспроизведены до
исправления: [red-controller-cancellation.json](red-controller-cancellation.json).

Контроллер54 получает исходящую сессию до RTC/capture await, освобождает публичный
Future запуска по явной отмене и проверяет поколение после асинхронных границ.
SDK проверяет отмену до/после TURN, регистрации и подготовки; ошибки очищают
маршрутизацию только своей сессии. Поздний результат захвата освобождается
существующей защитой CallSession. Подготовка ограничена45с независимо от
последующего прозвона; соединённый разговор этим таймером не прерывается.

Локальный клиент54 с настоящими Matrix, криптохранилищем и WebRTC прошёл
cancel→retry до возврата старого захвата: новая попытка через884мс, доставка1076мс,
оба клиента соединены. Возврат старого захвата остановил только его дорожки;
новый разговор сохранился. После отбоя оба источника остановлены.
Это синтетическая тишина, не микрофон и не проверка качества звука.

## HTTP429 во время установления звонка

При серии повторов/встречных звонков локальный Synapse с исходным лимитом
сообщений вернул429 `rc_messages` для encrypted room send. После этого вызывающий
уже завершил сессию, а получатель ещё показывал разговор. Серверное свидетельство
без аккаунтов/room IDs: [local-synapse-429.json](local-synapse-429.json).
Это воспроизведение на стенде, причина конкретного звонка владельца не доказана.

До исправления шесть проверок этой ветки падали:
[red-signalling-rate-limit.json](red-signalling-rate-limit.json).
SDK теперь повторяет только явный `M_LIMIT_EXCEEDED`, максимум3 раза и с суммой
ожидания до15с. Приоритет имеет числовой `Retry-After`, затем `retry_after_ms`;
при отсутствии подсказки —1с, минимальное ожидание100мс. Нераспознанный формат
заголовка или задержка сверх бюджета завершаются ошибкой без раннего повтора.
Другие ошибки, включая неоднозначный сетевой отказ, автоматически не повторяются.
Envelope шифруется один раз; transaction ID и ciphertext сохраняются. Отменённый
invite/answer не отправляется повторно; terminal hangup/reject разрешён после
локального завершения. Ошибка локального offer теперь отправляет hangup вместо
одного локального terminate. Серверные лимиты не изменены.

Договорённость о задержке и идемпотентности:
[Matrix Client–Server API](https://spec.matrix.org/latest/client-server-api/#rate-limiting).
Исходные лимиты:
[Synapse configuration](https://element-hq.github.io/synapse/latest/usage/configuration/config_documentation.html#rc_message).

## Условия измерений

Два новых собственных QA-профиля во внутреннем браузере, два loopback origin,
обычный `lib/main.dart`, локальный Synapse/control и отдельный авторизованный TURN.
Регистрация/вход/ключ восстановления и звонки выполнялись через UI. Профили
владельца и production-переписки в стенд не копировались. Recovery keys и токены
не входят в свидетельства.

[qa-media.js](qa-media.js) добавляется только в игнорируемый результат локальной
сборки перед flutter bootstrap. Он ограничен loopback, явно показывает замену
медиа в интерфейсе и создаёт нулевой аудиосигнал/счётчик видеокадров. Кнопки
позволяют задержать один capture и вернуть его позже. SDK, Matrix, шифрование
хранилища, DTLS, TURN и авторизация приложения остаются настоящими. Скрипт не
попадает в production-ассеты. Метрики показывают исходные дорожки fixture;
не объявляют проверенными все платформенные копии или акустическое воспроизведение.
