# Эмодзи сверки и запуск webapp — 25 октября 2026

Пользователь в итоге подтвердил устройство числовым SAS и вошёл. В последней
попытке Safari уже показывал вкладки «Эмодзи / Код» и три числа, но не картинки.
До этого установленное webapp однажды оставалось белым около двух минут.

Функциональная правка `27849677d0f858f9e08815aceb3f85df600d2cf3` влита в main
и опубликована на VPS и локальном стенде. [Build and deploy #23](https://github.com/kerbermeister/voicechat/actions/runs/40188904749)
успешен, режим web. Последующее уточнение меняет только комментарий bootstrap
и документацию, не исполняемый код.

- Все 64 SAS-символа поставляются PNG из Noto Emoji, около 281 KiB суммарно.
  Отображение не требует внешнего emoji-шрифта; сохранены подписи для чтения
  с экрана, текст при ошибке загрузки и числовой способ сверки.
- Bootstrap не передаёт serviceWorkerSettings. Убран вызов SDK, который ждёт
  getRegistration без тайм-аута до загрузки приложения. Настоящий код SDK
  с намеренно зависшим ответом воспроизводит блокировку до правки и запуск после.
  Cleanup worker может перезагрузить контролируемые страницы при обновлении,
  но постоянный цикл перезагрузок не доказан: SDK проверяет наличие регистрации.
  Первая упрощённая модель этого условия не учитывала; её вывод о цикле отклонён.

216 клиентских тестов прошли, 3 optional пропущены; анализатор без замечаний.
Новый тест декодирует все 64 изображения, проверка диалога использует экран
320×640 и переключает SAS на числа. Собраны release web и debug APK arm64,
в APK проверено наличие всех PNG. CI прошёл серверные/клиентские проверки и
пересоздал crypto assets после изменения pubspec; локальная сборка использует
эти свежие артефакты из образа подтверждённого релиза.

На публичном адресе сверены SHA-256 всех 64 PNG; bootstrap запускает loader
без serviceWorkerSettings. JS совпадает с работающим контейнером. API здоровы,
no-cache/COOP/COEP сохранены. Fingerprint, digest control, ID/StartedAt/RestartCount
backend-контейнеров неизменны; rollback pointer указывает на 422ea49, каталог
сохранён. Локальный JS совпадает с новой сборкой и содержит локальные endpoints;
предыдущая сборка оставлена для отката. Хранилища пользователей не очищались.

Во внутреннем desktop-браузере видны экран входа и опубликованный PNG;
ошибок запуска в доступной консоли нет. [Результаты](ios-sas-assets-release-evidence/verification.json),
[workflow](ios-sas-assets-release-evidence/workflow-success.jpg),
[запуск](ios-sas-assets-release-evidence/desktop-launch.jpg).

Точная причина двухминутного ожидания на физическом iPhone не подтверждена:
нужна повторная проверка установленного webapp после этого выпуска.
