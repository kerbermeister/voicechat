## Эмулятор: настоящая доставка FCM и группы

1 ноября2026, опубликованный APK1.16.0+38 с SHA-256 из отчёта публикации,
Google APIs Android15/API35 arm64. Два отдельных одноразовых аккаунта;
существующие пользовательские профили и Keychain не затрагивались.

- Отказ в POST_NOTIFICATIONS не создаёт серверную Android-привязку;
  после разрешения зарегистрированы реальный FCM token и одна привязка.
- Прямой тестовый callback шлюза доставлен через настоящий FCM: в фоне
  показано нейтральное «Новое сообщение», в foreground дубль подавлен.
  Доставка повторена после `am kill` с подтверждённым отсутствием процесса
  и после холодной загрузки до открытия клиента. Это не force-stop.
- Отдельная группа `is_direct=false`, Megolm, два участника. Два сообщения
  отправлены обычным UI Android-клиента; для каждого реального зашифрованного
  Matrix event подтверждена запись FCM-доставки именно этого события.
  Первое уведомление получено в фоне на защищённом PIN экране, второе —
  после `am kill` при отсутствующем процессе. Нажатие открыло нужную группу,
  оба контрольных текста видны расшифрованными. Перед открытием с lock screen
  Android запросил PIN. Это проверка сообщений, не групповой конференции.
- Отдельные API-fixture вызовы проверили CallStyle, нативное отклонение без
  Flutter, удалённую отмену и самостоятельный expiry после45 секунд.
  Для video-fixture на PIN keyguard реально открыт нейтральный
  IncomingCallActivity; ответ требует разблокировки, CAMERA/RECORD_AUDIO
  до разблокировки не выданы. API-fixture без шифрованного call event
  не доказывает ответ или медиасоединение.
- Настоящий голосовой вызов из UI второго Android создал системное входящее
  уведомление при отсутствующем процессе получателя. При попытке ответа
  завис сам QEMU (main loop и оба virtual CPU); принятие/медиа не засчитаны.
  Программный рендерер также сообщил invalid ColorBuffer; повтор с host renderer
  позволил продолжить. Сбой среды не объявляется дефектом клиента.
- В открытом клиенте настоящий голосовой звонок принят, обе стороны перешли
  в разговор. При холодном ответе выявлен отдельный дефект клиента: уведомление
  открывало разговор до создания ChatActions (`actions!`, main.dart). В39
  обработка уведомления перенесена после готовности chat actions и VoIP delegate,
  затем явно применяются уже полученные приглашения. Добавлен тест ожидания
  загрузки комнаты и однократного применения сохранённого ответа. Повтор39
  на эмуляторе ещё требуется; слышимость и медиарасшифровка не доказаны.

Найдена устаревшая подпись Android-настройки уведомлений: она ещё сообщает,
что доставка после закрытия недоступна. Текст исправлен в кандидате39; новый пакет пока не выпущен.
Аппаратная приёмка и оставшиеся сценарии остаются в UA-18.
