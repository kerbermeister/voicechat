# Повторные и встречные звонки — кандидат 1.19.5(53)

Замечание владельца: iPhone PWA иногда не позволяет перезвонить после пропущенного
входящего; повторная попытка тоже может не доходить. Другие устройства и отсутствие
входящего у собеседника пока предположения. Таблица сценариев и пользовательский
остаток ведутся в [едином реестре UA-04](../../user-acceptance.md#ua-04).

## Найденные причины и изменения

В SDK просроченное приглашение удаляло весь общий sync batch, включая свежий
callback. Terminal-событие фильтровало совпавший call ID без проверки room ID.
Теперь фильтруется отдельная копия, только по соответствующим комнате/вызову;
исходный список и content остаются неизменными. Ошибка одного события логируется
и не обрывает обработку последующих независимых вызовов в том же batch.

Завершение старой сессии возвращалось до удаления routing и освобождения RTC,
если новым currentCID уже владел другой звонок. Теперь старые ресурсы удаляются
всегда, новый владелец сохраняется. Оставшийся owner guard также проверяет room ID.
Контроллер хранит DirectCall по объекту CallSession, а не глобальному call ID;
старый callback не закрывает сессию другого чата с тем же ID. Дедупликация
истории завершения учитывает комнату. Отмена во время RTC allocation освобождает
поздний peer и не продолжает capture. Ошибки RTC/remote SDP завершают сессию и
передаются вызывающему коду. Peer снимается с владения до awaited close/dispose;
dispose выполняется и при отказе close.

Входящий lifetime игнорировался: после RTC/SDP запускался новый полный таймер.
Теперь учитываются age, ожидание предыдущих событий sync, TURN/проверка доверия
и оставшееся время до RTC setup. Таймер не превышает локальный лимит и работает
во время allocation. Просроченный входящий не открывает микрофон.

Busy-ветка подавляла UI emit через reject и вместе с ним теряла сетевой отказ.
Теперь отправляется terminal user_busy без лишней локальной карточки. При двух
встречных исходящих текущая политика даёт обеим сторонам busy, затем разрешает
свежую попытку. Автоматический ответ не добавлен. Интерфейс объясняет «занято»
только для своей исходящей сессии; поздний исход старого вызова не меняет новый.

## Проверки и границы

Отрицательные результаты до соответствующих исправлений сохранены в red-*.json.
В них указан base release и состояние рабочего дерева: часть независимых53
исправлений уже могла быть применена. Это не утверждение, что каждый red запуск
выполнен на полностью неизменённой52.

Регрессии используют реальные VoIP/CallSession, synthetic RTC/transport и
управляемые таймеры. Три последовательных цикла timeout, reject и remote cancel
проверяют повторный invite и поздний hangup предыдущего ID. Проверки не включают
настоящую доставку Matrix/push, физический iPhone/Xiaomi, акустический lip-sync
или потери WAN. Они доказывают исправление конкретных ветвей SDK, но не причину
каждого пользовательского сбоя.

Адресные проверки:50 PASS; Python849/4skip, анализ клиента/изменённого SDK PASS.
Нативный Mac:3 цикла реального RTC, отмена до ответа, DTLS/RTP и восстановление
после2с паузы PASS; сигнализация в памяти, воспроизведение звука выключено во
избежание акустической петли. Полный клиентский прогон:614 PASS/4 условных skip. Производственные
web/macOS/Android пока52; выпуск53 ещё не выполнен. Криптографические алгоритмы,
проверки доверия, TURN credentials и параметры качества не ослаблены.
