# Мобильные звонки и сообщения — 25 октября 2026

Локальная реализация восьми задач из [плана](../tasks/14-mobile-calls-and-messaging.md).
В production не выпущена; реальный iPhone не подключён. По уточнению пользователя
история остаётся обычной лентой, перенос старых joined-сообщений отменён.

## Что изменилось

- Регистрация автоматически понижает регистр только логина. Подсказка
  «Логин · строчные a–z» видна и на коротком экране. Пароли не преобразуются.
- Кружок автоматически начинает запись. Нажатие «Отправить» либо отпускание
  удержания завершает запись и отправляет её без промежуточного прикрепления.
  Сдвиг влево/«Отмена» удаляет запись; отмена во время start не отправляет файл.
  Прерывание звонком или inactive сохраняет запись черновиком. Существующий путь
  отправки сохраняет файл при ошибке и восстанавливает текстовый черновик.
- Личная камера на native переключается средствами WebRTC. Web выбирает
  user/environment без зависимости от enumerateDevices, освобождает прежнюю
  камеру и пытается вернуть её при отказе. Микрофон не пересоздаётся. Возврат
  камеры использует capture constraints; отказ настройки bitrate больше не
  сбрасывает успешно открытую камеру. Зеркало только для передней камеры.
- Плеер подхватывает позднюю аудиодорожку; неизменные дорожки не переподключаются.
  Browser Web Audio разблокируется в пользовательском событии, включая отпускание
  касания и VoiceOver click. Remote media получает повтор play; окно звонка
  предоставляет ручное включение звука. Локальное видео остаётся muted.
- Один собеседник занимает основную область. Своё превью — маленькое в углу,
  с возможностью скрытия без изменения capture/publication. Групповые собеседники
  остаются в сетке. Качество видео и отдельная демонстрация экрана сохранены;
  короткий экран/крупный текст допускают прокрутку содержимого, controls доступны.
- Новые группы создаются с shared. Перед новым приглашением старая группа
  получает эту политику при наличии прав; это не открывает прежние joined-события.
  Недостающие ключи доступной истории запрашиваются при открытии и пагинации.
  Автоматическая передача требует независимой проверки точного устройства,
  актуальной shared-политики и обоих участников в группе. TOFU этого не заменяет.
- Web Push: отдельный service worker, запрос разрешения прямо из кнопки,
  защищённая регистрация/отзыв текущего Matrix device, event_id_only pusher,
  стандартное шифрование и VAPID через pywebpush. VAPID key постоянный в control
  volume, включённом в существующий согласованный backup. Provider endpoints
  ограничены, redirects отключены; дубликаты не доставляются повторно, 404/410
  отзывают подписку, transient error возвращает retryable 503. Push не содержит
  текстов, авторов, room/event IDs или ключей E2EE. Worker проверяет account binding;
  выход отзывает подписку и закрывает уведомления.

## Проверки

Использован закреплённый Flutter 3.47.7 из `.prototype/tools/flutter`.
Системный Flutter оказался устаревшим (Dart 3.8.1) и не использовался для результата.
Python Web Push зависимости установлены в отдельное временное venv; полный набор
версий закреплён в `infra/push-requirements.txt` и подключён во всех CI-вызовах
серверных тестов, а также в control Dockerfile.

Новые тесты покрывают преобразование логина, шесть сценариев mock камеры,
переключение native камеры без остановки микрофона, позднюю аудиодорожку без
повторного сброса, размеры превью и сохранение remote element при скрытии,
автоматические ключи и пять отказов доступа, trust boundary HTTP gateway,
provider errors/retries/dedup/rotation, права файлов и сохранность VAPID key.

В push-тесте выполнены настоящее RFC 8291-шифрование/VAPID-подпись и расшифровка
payload браузерным приватным ключом; чужой ключ не расшифровывает его.
HTTP push provider при этом подменён: это не доказательство доставки через Apple.
JS-тесты используют имитацию браузерных API: trusted activation, отказ разрешения,
Home Screen requirement, постоянная привязка worker и игнорирование старого аккаунта.

## Приёмка и выпуск

Docker daemon недоступен, поэтому control-образ и настоящий Compose gateway не
собраны/не прогнаны. Production baseline не запрашивалась, release-артефакты не
собирались. Новые protected server/Dockerfile/workflow пути требуют `full` независимо
от web-части; нельзя выпускать этот набор через web-only. Существующие посторонние
правки Android updater сохранены и не объявлены частью этой итерации.

Нужна физическая проверка списка из плана на iPhone и Android. Web Push на iPhone
требует Home Screen app и iOS 16.4+. В фоне будет системный звук по настройкам iOS,
а не длинный ringtone/CallKit; в открытом приложении — собственный ringtone после
разблокировки аудио. Старые joined-сообщения по решению пользователя не мигрируются.

Источники контрактов: [WebKit Web Push](https://webkit.org/blog/13878/),
[Matrix gateway](https://spec.matrix.org/unstable/push-gateway-api/),
[pywebpush](https://pypi.org/project/pywebpush/),
[Matrix history visibility](https://spec.matrix.org/v1.1/client-server-api/index.html#room-history-visibility).
