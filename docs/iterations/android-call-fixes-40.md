# Android: исправления звонков, кандидат40

01.11.2026. Основание: отчёт владельца о Xiaomi на предположительно39;
модель/Android неизвестны. Дополнение: кнопка аудиовыхода существует, но не работает;
уведомления заработали только после ручной выдачи системных разрешений.
Текущий статус пользовательских сценариев ведётся только в [реестре](../user-acceptance.md).

Прямой звонок использовал LiveKit AudioManager, хотя захват и маршрутизация
принадлежат flutter_webrtc. Теперь команда идёт владельцу аудиосессии;
успешное состояние отображается кнопкой. Групповой звонок сохраняет LiveKit.

IncomingCallActivity самостоятельно запрашивала снятие keyguard. Вместо этого
после проверки актуального push она открывает тот же Flutter engine в режиме
экрана звонка поверх блокировки. Корневой gate сохраняет чат смонтированным,
но исключает его и прежние модальные окна из отображения/семантики.
Нативная непрозрачная шторка снимается только после кадра gate; чат не показывается
на промежуточной загрузке. Блокировка ОС сохраняется, системные проверки не отключаются.

Повторный receive одного notice раньше использовал WorkManager KEEP: пришедшая
во время обработки отмена могла потеряться. APPEND_OR_REPLACE сохраняет следующий
resolve после текущего. Уже звонящее insistent-уведомление не перезаписывается
Matrix-wakeup с onlyAlertOnce; AppSounds проверяет активное системное уведомление
и не запускает второй одновременный гудок; исчезновение приглашения снимает уведомление по session.

Первое знакомство больше не сохраняет пустую запись без ключей; прежняя пустая
запись восстанавливается. Поздний master принимается лишь с проверенной SDK цепью
подписи прежнего доверенного устройства этого же пользователя. Доверие сохраняется
до выдачи ключей; изменённые pinned fingerprints и новые неподписанные устройства
сохраняют прежний отказ. Проверки членства, отзыва и E2EE не ослаблены.

Таймер скрыт при нулевой длительности, которую движки начинают считать после
соединения/получения медиаключа. Предпросмотр кружка получает квадрат через
AspectRatio после ограничения ширины диалогом. Нативный видеорендерер перепривязывается
при замене объекта stream/track даже с прежними идентификаторами. Причинность для
плавающего зависания на Xiaomi потребует проверки получаемых кадров на телефоне.

Проверки и публикация будут дописаны по фактическим результатам. Кандидат не равен
проверке реального телефона; на старте физический Android к ADB не подключён.

Дополнение владельца01.11: rollout40 однократно ставит notification preference=true
на каждой установке/аккаунте Android, macOS и web, включая прежнее false.
Маркер отдельный от appBuild, поэтому следующее ручное выключение не сбрасывается
при рестарте или следующем выпуске. Native запрашивает разрешения; web с granted
автоматически восстанавливает subscription/binding, без granted показывает кнопку,
сохраняющую требуемый браузером пользовательский жест. Разрешения ОС не подделываются.
