## Реализация

Общий Android/web Flutter-клиент: альбомы с подписью, предварительный просмотр, уменьшение сторон фотографии вдвое, fullscreen gallery; реальные PCM-волны голоса, остановка в черновик и текстовая подпись; видео/видеокружки/файлы; два списка участников, входящие приглашения, все печатающие, одна реакция и её авторы; семь тем; аватары с кадрированием; поиск и календарь; отдельное окно звонка и звуки.

Публичные свойства: `prototype/client-policy.json`, GET control API `/config`. Файл перечитывается сервером при запросе; клиент проверяет его не чаще раза в 30 секунд и сохраняет последнюю валидную копию в защищённой базе. Лимиты: фото 24, масштаб 0.5, JPEG85, текст 16000, голос 180 с, видеокружок 60 с, видео/файл 300 МиБ. Ограничения смыслового содержимого при E2EE исполняет доверенный клиент; это не защита сервера от модифицированного клиента. Synapse самостоятельно ограничивает каждый media upload.

## Большие файлы и защита данных

Файл разбивается на части не больше 4 МиБ. Каждая зашифрована штатным Matrix SDK (AES-CTR + SHA-256 ciphertext); ключи и упорядоченный манифест отправляются одним Megolm-сообщением после повторной проверки устройств. Сервер не получает plaintext или ключи частей. Совместимость такого сообщения требуется на обоих клиентах VoiceChat; произвольный сторонний Matrix-клиент его не соберёт.

Подготовленные ciphertext-части находятся в собственной таблице SQLCipher на Android или отдельной IndexedDB с AES-GCM и привязкой к профилю/ID части в web vault. Манифест очереди не содержит base64 всего файла. После подтверждения/отмены части удаляются. Прерванную подготовку после аварийного завершения нельзя угадать: запись можно отменить и выбрать исходный файл заново. Уже загруженные части переиспользуются при повторе; Matrix transaction ID сохраняется.

Получение проверяет размер, порядок, количество, origin media-эндпоинта, HTTP-ответ, ciphertext hash каждой части. Отдача видео: локальный HTTP с непредсказуемым URL в Android; service worker с привязкой к ID исходной вкладки в web. Оба читают расшифрованные части по диапазонам, без plaintext-кэша на диске. Web worker не использует CacheStorage/IndexedDB, ответы `no-store`; URL отзывается при закрытии. Для сохранения используются системный SAF Android, File System Access API браузера или потоковый download через worker. Пользовательский экспорт — намеренно расшифрованный файл в выбранной папке.

Запись камеры на Android временно создаётся camera-плагином в приватном cache приложения (защита Android/FBE, не SQLCipher). Удаляется после подготовки защищённой очереди или отмены; отдельная очистка после аварии процесса требует проверки. Веб-камера использует временный Blob URL. Аватары — открытые Matrix-метаданные, предупреждение показано до сохранения.

## Поиск, звонки и звук

Общий поиск проверяет до 1000 локальных событий каждого вступленного чата; можно увеличить охват до 10000. Поисковая фраза не передаётся серверу. Календарь использует Matrix timestamp-to-event и контекст, а не plaintext-поиск на сервере. Полнота ограничена доступными ключами и локальной историей.

Ожидание вызова отдельно от подключения. Тайм-аут 45 с; отсутствие presence не отменяет вызов само по себе. Длительность личного вызова начинается с WebRTC Connected; группы — с успешного E2EE-аудио. Старым событиям длительность не придумывается. Новая карточка истории не является серверным журналом биллинга.

Звуки сгенерированы локально (собственные WAV, без внешних ассетов). Звук отправки только после подтверждения, входящие — новые сообщения после входа, без истории/правок/реакций. Есть выключатель. Браузер может блокировать autoplay; это отображается в настройках. Физические маршруты/гарнитуры и фоновые push-вызовы требуют отдельной приёмки.

### Временные сообщения — реализация 22 октября

Срок задаётся в `prototype/client-policy.json`: `temporary_min_seconds=10`, `temporary_max_seconds=600`, `temporary_step_seconds=10`. Локальный control API читает конфиг при запросе, клиенты обновляют последнюю валидную политику каждые 30 секунд. Ползунок и кнопка таймера относятся к следующей отправке: тексту, альбому, голосовому и файлам. В долговечной зашифрованной очереди сохраняется длительность, а не дата истечения: ожидание сети/подготовка вложений не расходуют срок.

Matrix-конверт сообщает серверу только длительность `dev.voicechat.ttl_seconds`; содержимое и файловые ключи остаются в E2EE. Synapse-модуль проверяет серверные границы и подставляет `org.matrix.self_destruct_after` по собственным часам. Включён штатный `enable_ephemeral_messages`: таймеры хранятся PostgreSQL и исполняются без открытого отправителя. Правка не может продлить deadline оригинала. Для проверки правки используется API установленного Synapse; версию сервера фиксируют digest Compose и отдельная реальная проверка.

На клиенте срок считается от `origin_server_ts`; истёкший текст не показывается в истории/поиске. Даже без ключа срок доступен из зашифрованного конверта; пустое серверное событие после истечения скрывается, не запускает восстановление ключей. Карточка имеет рамку/таймер и вращающийся значок, при истечении содержимое заменяется на секундную анимацию растворения без текста. Reduced motion отключает движение. Перерисовывается только карточка. Цитаты временных сообщений содержат обозначение и ссылку, без постоянной копии исходного текста.

Ограничения: механизм не стирает уже полученные копии, буфер обмена, скриншоты, ранее сделанные резервные копии или отдельно сохранённые вложения. Зашифрованные media blobs не удаляются по этому таймеру: сообщение/ключи исчезают из выдаваемого события, физическая очистка media требует отдельной политики хранения. Отображение таймера зависит от часов устройства; серверное истечение — от часов сервера. Старые сторонние клиенты могут сохранять локальные копии. Это не обещание гарантированного уничтожения данных.

Проверки: серверный срок/границы/правки/обычные сообщения — `prototype/verified-temporary-server-run.json`; адресные Flutter-тесты таймера, поиска, очереди и цитат, семь тем/320 px — PASS. Сквозная UI-приёмка и Android фиксируются отдельно; нельзя считать обычную web-сборку доказательством Android-камеры/фонового поведения.

### Отложенные сообщения — 22 октября

`prototype/client-policy.json` задаёт `schedule_max_seconds=172800` (48 часов). В композере доступны календарь/часы и отдельный список расписания текущего чата: дата в местном часовом поясе, состояние, отмена до начала отправки. Сервер сравнивает абсолютную дату с собственными часами. Выбор относится к следующему сообщению и совместим с текстом, фотоальбомом, голосовым, видео и файлами; временный таймер начинает действовать при публикации.

Используется существующий control API и один SQLite-файл `scheduled/messages.sqlite` в его постоянном Docker-томе. Внешний планировщик и дополнительные VPS не нужны. Штатный Synapse MSC4140 здесь не подошёл: установленная версия удаляет задание даже после неудачной публикации. Небольшая очередь сохраняет ciphertext при сбое, повторяет временные ошибки, хранит состояние и исходный зашифрованный конверт при постоянном отказе. В SQLite нет открытого текста, файловых ключей или access token пользователя. Отдельные вложения загружаются зашифрованными до постановки задания.

Перед постановкой клиент создаёт Megolm-конверт и передаёт ключи разрешённым устройствам обычным механизмом Matrix. Сервер связывает задание с аккаунтом/устройством и отпечатком состава участников и всех опубликованных Curve25519/Ed25519-ключей. Защищённый Synapse endpoint перед фактической публикацией проверяет действующий аккаунт и устройство, членство/согласие личного контакта и тот же состав ключей. При изменении публикация прекращается с явной ошибкой; сервер не переупаковывает E2EE для нового состава получателей.

Задание живёт независимо от вкладки отправителя. Один и тот же transaction ID преобразуется в стабильный ID задания и Matrix-транзакцию. Потеря HTTP-ответа/перезапуск повторяют её без дубликата. Отмена локального неподтверждённого задания создаёт серверную tombstone: поздний create не возвращает его в расписание. После начала публикации отмена недоступна, поскольку ответ мог потеряться уже после принятия Matrix. Успешные/отменённые задания освобождают сохранённый конверт; при окончательном отказе ciphertext остаётся доступен владельцу через API. Список не обещает отправку при отзыве доступа.

До серверного подтверждения зашифрованная локальная очередь хранит исходный черновик. Если время прошло во время офлайна или подготовки большого файла, оно не заменяется немедленной отправкой: доступен выбор нового времени. Такое отклонённое задание не блокирует обычные сообщения того же чата. Временный отказ API повторяется с прежним конвертом; потерянное подтверждение проверяется до новой сверки ключей.

Проверки серверной очереди: `test_scheduled_messages.py`, `test_client_policy.py` и `verified-scheduled-server-run.json`. Последний проверяет реальный Synapse с непрозрачным fixture, а не клиентскую расшифровку. UI/E2EE-приёмка записывается отдельно в `verified-scheduled-ui-run.json`; физический Android, реальная доставка push и внешний VPS этим не проверяются.

Docker-конфиг публичных лимитов сохраняется в томе media-config, читается через `VOICECHAT_CLIENT_POLICY` при каждом запросе, входит в зашифрованный deploy-backup. Configure добавляет недостающие новые значения, сохраняя изменения оператора. Адресный тест подтверждает повторное чтение лимита и отказ неверному типу; тест миграции — сохранение своих значений и повреждённого файла без перезаписи. См. `infra/README.md`. Это проверка кода и локального API, не заявление о состоявшемся внешнем деплое.

Просмотр задания по нажатию расшифровывает содержимое на устройстве владельца. Он не регистрирует фиктивное событие в replay-индексах Matrix: до публикации у задания ещё нет event ID. Комната/тип/владелец/ID проверяются; отсутствие ключей не удаляет черновик.
