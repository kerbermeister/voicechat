## Причина сбоя

API на порту 8090 не был запущен. Обычное сообщение проходило напрямую через Synapse, а для временного Synapse запрашивал `/config`, чтобы проверить срок жизни. При отказе соединения проверка корректно запрещала публикацию с HTTP 403. Клиент показывал это как отсутствие подтверждения и сохранял запись первой в очереди комнаты; следующие записи ожидали её отправки.

После запуска API сервер подтвердил исходные транзакции Элис с прежними transaction ID, затем следующие записи очереди. Новые копии пользовательских сообщений вручную не создавались.

## Изменения

Перед публикацией временного сообщения клиент проверяет доступность и формат серверной политики. Сервер продолжает независимо проверять срок жизни. При сбое очередь сохраняется, повторная попытка использует тот же идентификатор, порядок в комнате сохраняется. При явном отказе сервера показывается отказ; следующие записи обозначаются как ожидающие предыдущую запись.

Панель «Запланировано · N» считает подтверждённые сервером задания в состояниях `pending`, `retry`, `sending`, `failed` только для текущей комнаты. Отправленные и отменённые задания исключены. Неотправленные в API локальные черновики остаются в обычной очереди отправки. Счётчик обновляется после действий и каждые пять секунд; при потере сети последнее известное число помечается как не обновлённое. Содержимое расшифровывается на устройстве по существующим ключам, без записи plaintext на сервер.

## Запуск

Docker-сервисы Matrix/PostgreSQL/LiveKit запускаются прежним Compose. Основной сайт и обязательный API теперь запускаются вместе:

```sh
python3 prototype/serve_app.py
```

Используется существующий `infra.supervise`: при остановке одного дочернего процесса завершается вся пара. Базы и конфигурация `.prototype` сохраняются. Оба HTTP-порта привязаны к loopback. Для отдельной статической галереи остаётся `prototype/serve_web.py`.
