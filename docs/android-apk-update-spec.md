# Ручное обновление Android через APK с сервера

Спецификация от 25 октября 2026. Реализовано локально в кандидате 1.1.0+2.
[Проверки и оставшиеся условия выпуска](iterations/13-android-apk-update.md).
[План реализации](tasks/13-android-apk-update.md),
[версии](app-versioning.md), [история изменений](app-changelog.md).

## Цель и границы

Пользователь обновляет установленный VoiceChat, сохраняя аккаунт, локальную
историю, настройки и ключи E2EE. Единственная точка запуска — кнопка
«Проверить обновления». Проверок при старте, входе, возврате из фона, по таймеру
или push нет. Нет автоматической загрузки, установки, принудительного обновления
и блокировки старой версии ради предложения обновиться.

Первый вариант: один канал выпуска, один универсальный APK, один сервер
обновлений, полный файл без delta и фоновой докачки. Google Play, смена ключа
подписи, перенос между разными applicationId и миграция debug → release с другой
подписью не входят в обычный сценарий обновления.

## Пользовательский сценарий

В Android-настройках добавить «О приложении»: установленная версия и номер
сборки, кнопка «Проверить обновления». Переиспользовать этот экран со страницы
входа, чтобы проверка не требовала действующей Matrix-сессии. Веб не показывает
кнопку установки APK. Открытие экрана само по себе не обращается к серверу.

1. Нажатие «Проверить обновления» запрашивает только описание актуального выпуска.
   Повторное нажатие во время запроса не создаёт второй запрос.
2. При той же или более старой сборке: «Обновлений нет». При несовместимости
   Android: «Новая версия не поддерживает эту версию Android». Ошибка сети или
   некорректный ответ показываются как ошибка проверки, а не отсутствие обновлений.
3. При новой совместимой версии показать текущую и новую версии, размер загрузки,
   краткое «Что нового», предупреждение о закрытии приложения при установке.
   Кнопки: «Скачать и установить» и «Не сейчас».
4. Только «Скачать и установить» разрешает загрузку конкретного показанного APK.
   Прогресс в байтах/процентах и «Отменить» доступны во время загрузки. Отмена
   закрывает запрос и удаляет частичный файл. Повтор после ошибки — вручную.
5. После загрузки выполняются проверки файла. Если Android требует разрешить
   установку из этого источника, показать объяснение и кнопку открытия системных
   настроек. Отказ оставляет текущую версию рабочей. Возврат из настроек даёт
   кнопку «Продолжить установку», без автоматического открытия установщика.
6. Передать проверенный APK системному установщику. Android запрашивает отдельное
   подтверждение установки; это обязательный шаг после подтверждения в приложении.
7. После обновления пользователь открывает приложение. Оно читает установленную
   версию из Android и восстанавливает прежний локальный профиль обычным путём.
   Не требовать нового входа, создания Matrix-устройства или recovery key вследствие
   самого обновления; существующие правила блокировки/отзыва сессии сохраняются.

Активный звонок, демонстрация экрана, запись или незавершённое сохранение данных
блокируют переход к установке с объяснением. Пользователь завершает действие сам;
после этого нажимает «Продолжить установку». Проверять условие повторно перед
передачей APK системе. Черновики и очередь должны быть сохранены существующими
механизмами; отсутствие надёжного сохранения выявляется и исправляется до выпуска.

При уходе приложения в фон во время загрузки операция отменяется; возврат не
возобновляет её. Исключение — уже открытые системные настройки/установщик: это
ожидаемая часть ручного сценария, её результат обрабатывается без новой загрузки.
После гибели процесса сохраняется только локальная запись ожидаемой установки
(versionCode, sessionId), без секретов. Незавершённая загрузка не продолжается.
Сам факт открытия установщика не означает успех: при следующем запуске сверить
фактический versionCode. Неизвестный результат не объявлять успешным.

## Исходное состояние и совместимость подписи

- До реализации `pubspec.yaml` содержал `1.0.0+1`, release использовал debug-ключ.
  Теперь кандидат — `1.1.0+2`, release требует отдельный production-ключ.
- applicationId сохранён: `dev.voicechat.voicechat_probe`.
- `Prototype checks` собирает debug APK; готового production-процесса подписи
  и публикации Android-обновлений этим не подтверждено.
- `MainActivity.kt` уже использует MethodChannel; реализация расширяет этот подход.

Владелец подтвердил отсутствие ранее распространявшихся APK и release-ключа.
Для первого выпуска создан отдельный ключ; его внешняя резервная копия и CI secrets
ещё не настроены. При появлении существующих установок получить сведения: applicationId,
versionCode, SHA-256 сертификата и доступность соответствующего ключа подписи.
Секретный ключ не читать в отчёт и не коммитить. Фактические сертификаты
локальных/CI debug-сборок могут различаться.

Обновление должно иметь тот же applicationId и подписанта. В первом варианте
ротация сертификата не поддерживается. Нельзя исправлять несовместимость советом
удалить приложение или очистить данные: это нарушает цель сохранения хранилища.
При отсутствии пригодной доверенной цепочки для существующей установки её
поддержка блокируется и требует отдельного плана миграции. Нельзя выдавать
восстановление из backup за сохранение всей локальной истории и черновиков.
Production-выпуск на debug-ключе не допускается.

Старый APK без этой функции не получит её через собственный интерфейс: первую
совместимую сборку с функцией нужно установить вручную поверх него. Этот переход
также входит в проверку сохранности данных.

## Контракт сервера

Предлагаемый адрес: `GET /updates/android/latest.json` на каноническом HTTPS origin
из конфигурации сборки. Адрес не берётся из сообщения, deep link или произвольного
homeserver пользователя. Проверка публичная, без Matrix-токенов, ключей и account ID.

Ответ JSON, схема 1:

| Поле | Контракт |
| --- | --- |
| `schema` | Целое `1`; неизвестная схема — ошибка проверки |
| `applicationId` | Точное совпадение с установленным приложением |
| `versionName` | `MAJOR.MINOR.PATCH` по правилам версий |
| `versionCode` | Положительное целое; обновление только при строго большем значении |
| `minSdk` | Минимальный Android API APK, сверяется с устройством |
| `apkPath` | `/updates/android/<versionCode>/voicechat.apk` |
| `sizeBytes` | Положительный точный размер APK |
| `sha256` | 64 шестнадцатеричных символа, SHA-256 всего файла |
| `notes` | Непустой обычный текст «Что нового», максимум 4000 символов |

Предел metadata — 64 KiB, APK — 300 MiB; превышение отклоняется до установки.
Таймаут проверки — 15 секунд, бездействия загрузки — 30 секунд, всей загрузки —
15 минут. Лимиты проверяются и по реально прочитанным байтам, не только заголовкам.
Схему и типы валидировать строго; дубликаты полей отклонять. Неизвестные скалярные поля
схемы 1 можно игнорировать; вложенные объекты и массивы отклоняются. Размер, versionName/versionCode и minSdk генерируются
из готового APK, без независимого ручного дублирования.

Разрешён только указанный путь на том же HTTPS origin, без query, fragment,
`..`, закодированных обходов пути и перенаправлений. Ответы 3xx отклоняются.
Metadata возвращается с `Cache-Control: no-cache`; APK неизменяемый,
`application/vnd.android.package-archive`. Отсутствующие файлы возвращают 404,
а не HTML из SPA fallback. 404 metadata означает «Канал обновлений недоступен».
Описание изменений показывается как текст, без HTML и исполнения ссылок.

APK размещается в постоянном каталоге VPS, доступном web/Caddy только для чтения,
отдельно от каталога Flutter web. Релиз web не должен удалять APK. Публикация:
загрузить APK во временный файл → проверить → атомарно разместить по неизменяемому
пути → проверить публичную выдачу → атомарно переключить latest.json. Публикации
сериализуются. Старые APK сохраняются для уже начатых загрузок; автоматическая
очистка не входит в первый вариант. При отзыве выпуска вернуть предыдущий manifest:
уже обновившиеся устройства не понижают версию и ждут исправления с новым номером.

## Проверка и системная установка

Использовать имеющиеся `http`/`crypto`, Dart streaming I/O и небольшой Android
MethodChannel. Файл находится только в отдельном приватном cache-каталоге обновлений,
не в общедоступных Downloads и не целиком в памяти. Частичный файл не устанавливается.

Перед установкой сверить точный размер и SHA-256, package name, versionName,
versionCode, minSdk и сертификат APK с установленным приложением. Значения APK
должны совпадать с показанным manifest; несовпадение прерывает сценарий. Совпадение
сертификата из метаданных APK само по себе не доказывает корректность подписи всего
файла: окончательная криптографическая проверка выполняется Android при установке.
CI дополнительно проверяет готовый APK через `apksigner verify --verbose --print-certs`.

SHA-256 с того же сервера защищает от порчи, но не от захвата сервера. Доверие к
коду опирается на подпись APK и сохранность ключа издателя; сертификат из manifest
не является новым источником доверия. Захват сервера может скрыть обновления или
подменить notes, поэтому актуальность при таком захвате не гарантируется.

Нативная установка — `PackageInstaller` session для собственного пакета, с
`REQUEST_INSTALL_PACKAGES`, проверкой `canRequestPackageInstalls()` там, где API
доступен. На API 31+ явно `USER_ACTION_REQUIRED`; на младших поддержанных версиях
проверить системное подтверждение на практике. Silent-install привилегии не нужны.
Обработать `STATUS_PENDING_USER_ACTION`, отмену, нехватку места, несовместимость,
повреждение и отказ политики устройства. Callback привязан к собственной session,
проверяется на подделку; произвольный внешний intent не запускает установку.

Перед commit повторно проверить файл и установленную версию; писать в session
только проверенные байты. После завершения/отмены удалить только временные файлы
обновления и закрыть/abandon незавершённую session. После сбоя не удалять session,
которую система ещё устанавливает. Финальные ошибки Android являются решающими,
предварительная проверка свободного места не гарантирует успех.

## Инварианты сохранности данных

Сохранить applicationId, профиль `voicechat_probe_${Uri.encodeComponent(profile)}`,
файл `<name>.secure.db`, secure-storage ключ `database:<name>`, настройки Keystore
и shared preferences (`lastAccount` и связанные параметры профиля).
Источники: `matrix_probe.dart`, `local_store_native.dart`, `main.dart`.

Updater не вызывает logout, `eraseStore`, очистку preferences, создание нового
профиля или сброс криптографической идентичности. Сохраняются Matrix user/device ID,
локальные ключи, доверие устройств, локальная история и вложения в пределах текущей
политики хранения, черновики и очередь. Системный `allowBackup=false` сохраняется.

`resetOnError: false`, проверка существующей БД read-only перед writable-открытием
и отказ при отсутствующем ключе остаются обязательными. Ошибка открытия после
обновления показывает диагностику, сохраняет исходные данные и не пересоздаёт БД.
В рамках первой реализации формат хранилища не меняется. Будущие обновления SDK/БД
требуют отдельной проверки миграций, включая прерывание и повтор; невозможность
безопасной миграции блокирует выпуск. Обратная установка APK не является стратегией
отката данных. Исправление выпускается вперёд с большим versionCode.

## Приёмка

Обязательны автоматические отрицательные проверки и физический Android-переход
N → N+1 с тем же ключом подписи. До и после обновления сравнить user/device ID,
публичные отпечатки ключей и профиль, не записывая токены/секретные ключи в отчёт.
До включения сети прочитать уже закешированные сообщения и вложение, затем
проверить онлайн старую историю, новый личный/групповой E2EE текст и файл с
независимого второго клиента. Успех — фактическая расшифровка текста и совпадение
байтов файла. Проверить доверие, настройки, черновик, очередь без потери/дубликатов.

Проверить ручные отмены на каждом шаге, отказ разрешения/установщика, обрыв сети,
завершение процесса, недостаток места, неверные hash/package/подпись/версию,
старый manifest и несовместимый Android. Во всех отказах старое приложение и
данные остаются доступны. Запуск, вход, открытие настроек, фон/возврат и ожидание
не создают запросов обновления. Матрица и этапы — в плане реализации.
