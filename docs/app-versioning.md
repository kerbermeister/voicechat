# Версии приложения VoiceChat

Правила от 25 октября 2026 для следующих выпусков клиента.
Правила внедрены: экран версии, проверка pubspec/исходников/истории/APK и release workflow.
Первый кандидат — 1.1.0+2, публикация ещё не выполнена.
[История изменений](app-changelog.md), [план внедрения](tasks/13-android-apk-update.md).

## Номер версии

Пользователь видит, например, **1.2.3 (сборка 42)**:

- `MAJOR` — несовместимое изменение пользовательского контракта или обязательная
  миграция, требующая отдельного плана. Большая версия не разрешает потерю данных.
- `MINOR` — новая совместимая функция; PATCH сбрасывается в ноль.
- `PATCH` — совместимые исправления без новой пользовательской функции.
- Номер сборки — отдельное строго возрастающее целое для каждого нового
  распространяемого Android APK. Он не сбрасывается при смене MAJOR/MINOR.

Единый источник — `version: MAJOR.MINOR.PATCH+BUILD` в
`apps/client/pubspec.yaml`. Android получает `versionName` и `versionCode` от Flutter.
Верхний предел BUILD — 2100000000 (правило проекта); значение никогда не переиспользуется
для другого опубликованного APK. Отклонённый кандидат может оставлять пропуск.
Повтор доставки уже готового неизменённого APK сохраняет номер; новая сборка
кандидата получает новый BUILD. У следующего публичного выпуска растут и версия,
и BUILD; несколько непубличных кандидатов могут иметь одну версию и разные BUILD.

CI не подменяет версию несогласованными `--build-name`/`--build-number`.
При публикации сравнивает pubspec, фактический APK, manifest, тег и запись истории.
Пример будущего тега: `app-v1.2.3+42`. Commit и SHA-256 APK фиксируются в записи
выпуска. Сравнение доступности обновления выполняется по числовому versionCode,
не по строке `1.2.3`, дате или commit.

Версия описывает общий код клиента Android/web. В записи явно указываются выпущенные
платформы: web-выпуск не означает выпуск APK, серверный commit не заменяет версию
клиента. Экран «О приложении» показывает версию реально собранного клиента, а не
последнюю версию с сервера. Web получает те же сведения при сборке, Android — из
установленного пакета; для Android доступна ручная проверка обновлений.

## Первая baseline

До этой реализации в pubspec стояло `1.0.0+1`. Это было техническое значение,
а не подтверждённая история стабильных выпусков. Не приписывать ему задним числом
все изменения из отчётов об итерациях.

Владелец подтвердил отсутствие ранее распространявшихся APK. Выбран кандидат
`1.1.0+2`, отдельный постоянный ключ подписи; он ещё не опубликован.
Если появляются другие установленные сборки, перед выпуском инвентаризировать распространявшиеся APK,
их подписи и максимальные versionCode. Выбрать BUILD выше всех совместимых
установок; первую публичную версию определить по фактической baseline и объёму
изменений. Если `1.0.0` уже выдавалась пользователям, не переиспользовать её для
другого публичного выпуска. Выбор и свидетельства записать в историю.

## История изменений

`docs/app-changelog.md` — единая история, новые версии сверху. Во время разработки
заполняется раздел «Не выпущено» только по уже сделанным изменениям. Планируемые
функции остаются в задачах. Перед выпуском запись получает версию, BUILD, дату,
платформы, commit, тег и SHA-256 APK. Человеческое «Что нового» из этой записи
попадает в manifest; отдельный независимо написанный список не поддерживается.

Для каждого выпуска описать добавленное/изменённое/исправленное простыми словами,
ограничения, совместимость и действия пользователя. Пустые категории опустить.
Ссылки на приёмку содержат реальные проверки и явно непроверенные устройства.
Подготовленная запись отмечается «кандидат» до подтверждённой публикации;
«выпущено» ставится после проверки публичного файла/manifest. Отозванные выпуски
не удаляются: отмечаются причиной и исправляющей версией.

Шаблон записи:

```text
## MAJOR.MINOR.PATCH (сборка BUILD) — YYYY-MM-DD
Статус: кандидат / выпущено / отозвано
Платформы: Android / web (указать фактически опубликованные)
Commit: …; тег: …; SHA-256 APK: … (если опубликован)

Что нового:
- Наблюдаемое пользователем изменение.

Совместимость и действия: …
Известные ограничения: …
Проверки: ссылка на отчёт, версии Android и реальные устройства.
```
