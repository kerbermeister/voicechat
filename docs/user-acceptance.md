## Как пользоваться

- Сначала раздел «Можно проверять»: только доступный функционал и свой набор
  устройств. Условные строки ждут указанной почты/оборудования/тестового профиля.
- Дефекты и ещё не реализованные пожелания вынесены ниже: не просим повторять
  их приёмку до выпуска исправления. Уже принятые блоки тоже сохранены отдельно.
- Одна функция — один стабильный ID `UA-xx`. Роли, устройства, повторные релизы
  и близкие замечания дополняют эту запись, а не создают дубликат. Несколько
  подробных технических тестов могут соответствовать одному пользовательскому ID.
- Результат дописывать в существующую строку: дата, версия, устройство/ОС/браузер,
  что сделано, ожидаемый/фактический исход; `принято`, `частично`, `дефект` или
  `не проверено`. Неуказанную платформу не считать принятой по умолчанию.
- Агент сам выполняет доступные ему проверки: код, unit/widget/integration,
  браузерный UI, подготовку/очистку своих fixtures, сборки, подписи, выпуск,
  хеши/health/backup и безопасные аппаратные проверки при наличии доступа.
  Он не передаёт пользователю работу только потому, что её удобнее попросить.
- Тесты с выходом, отзывом устройств, восстановлением/очисткой — только на
  подготовленных одноразовых профилях; основной профиль и Keychain не очищать.
  Ключи, пароли, токены и приватную переписку в этот файл не помещать.
- Не автоматизировать пользовательский Chrome: разрешён внутренний браузер.

Известные устройства: iPhone 11 Pro / iOS 27.0.1; iPhone 17 Pro / версия iOS
не названа; MacBook / desktop macOS. В подтверждении пунктов пользователь
не перечислял устройства, поэтому не достраиваем полную платформенную матрицу.

## Можно проверять: доступный функционал и условные сценарии

Статус «Ожидает» означает отсутствие подтверждения именно пользовательского
результата на реальном устройстве; у функции могут быть успешные автопрогоны.
Наличие строки не объявляет функцию заведомо исправной: найденный сбой записываем
в неё. Для группового аудио → видео обе стороны должны быть обновлены; старый
аудиоклиент может блокировать включение камеры с объяснением, сохраняя разговор.
Неподдерживаемый системный захват экрана должен объясняться, а не считаться
успешной трансляцией. Непрерывный фон/звонок при закрытом процессе не обещается
там, где ОС этого не предоставляет.

## Платформы и внешние условия

- **Android:** физическая приёмка отложена владельцем до появления телефона.
  UA-37 — отдельный переход установки; звонки/запись/файлы проверяются по тем же
  функциональным UA, а не вторым полным Android-списком. Preview APK в CI не
  означает опубликованный подписанный production APK.
- **Старые macOS:** принят Mac владельца; macOS 12–14 и другие заявленные
  версии не считаются проверенными по этому результату (UA-38).
- **Firefox и другие браузеры:** в screen SDK-lab 24 октября было `media connection
  FAIL` для Firefox 153. Это не доказанный исход 1.6.1. Агент должен сначала
  повторить диагностику в разрешённой среде; затем пользовательские экран/звонок
  идут по UA-02/04/05 с отметкой браузера. Не создаём дубликат всех функций.
- **SMTP / системное Share / VoiceOver:** Mailpit, mock Share и AX-снимок не
  заменяют реальное письмо, внешний мессенджер и озвучивание. Эти условия
  отмечены соответственно в UA-21/22, UA-28, UA-36.
- **Clipboard:** в web доступны текст/изображения; произвольный файл как объект
  ОС поддерживается нативными путями Mac/Android. Не расширять пользовательское
  «копирование принято» на неподдерживаемый формат/неуказанную платформу (UA-39).
- **Системный фон:** iPhone PWA проверяется в UA-03/18; самостоятельные обещания
  непрерывного захвата, CallKit или неограниченного ringtone не приняты.

## Что не перекладываем на пользователя

Автоматические негативные security/парсинг-тесты, доказательство E2EE/отказа
старому JWT, нагрузка и resource leaks, намеренный production fault/rollback,
восстановление серверных volumes, подписи/ABI/minSdk, SMTP/FCM-настройка,
release secrets, GitHub Actions, Cache-Control/fingerprints и серверное сжатие —
работа агента/оператора по соответствующим планам. Проверка этих работ не
превращается в пользовательский пункт «проверить сервер». Архивные открытые
чекбоксы про отсутствие VPS/Actions или macOS-обновления не переоткрывают уже
состоявшиеся выпуски. Независимый security audit остаётся отдельной внешней
экспертизой, а не просьбой пользователю доказать криптографию через UI.

Серверный backup не заменяет пользовательские E2EE-ключи; его техническая
приёмка остаётся у агента, пользовательский результат восстановления — UA-24.
Отменённое владельцем восстановление старой истории Элис не возобновляется.
