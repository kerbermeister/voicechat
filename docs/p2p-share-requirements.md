# P2P Share · Beta — функциональные требования

27 октября 2026. Реализация в работе. [ТЗ](p2p-share-spec.md),
[пошаговый план и фактические проверки](tasks/18-p2p-share.md).

## Действующий объём

Исходная задача от 24 октября: Android/web, передача без серверного хранения,
согласие получателя, шифрование, целостность, прогресс и отмена.
Последнее решение пользователя 27 октября заменяет прежнее требование докачки:
**передача только здесь и сейчас, без паузы/продолжения и восстановления после
закрытия приложения**. Постоянная очередь ожидающих передач исключена.

Поддерживаемая архитектура охватывает браузеры на macOS/Windows, Safari/iPhone,
Android и нативный macOS. Будущий Windows-клиент использует тот же протокол;
его платформенная реализация и аппаратная приёмка не считаются уже готовыми.

## Пользовательский сценарий

1. Открыть отдельный раздел «P2P Share · Beta» и выбрать принятых друзей.
2. Добавить файлы кнопкой или перетаскиванием. Увидеть имена, размеры, общий объём,
   ограничения. До отправки можно убрать файл; ничего ещё не отправляется.
3. Нажать «Отправить». Получатель видит отправителя и состав пакета и отдельно
   принимает или отклоняет его. Передача содержимого начинается только после согласия.
4. Получатели работают независимо. У обеих сторон прогресс каждого файла:
   процент с двумя знаками и плавно заполняющееся кольцо вокруг иконки.
5. В любой момент можно отменить передачу. После окончательного обрыва/закрытия
   повторить отправку с начала, с новым согласием. Готовые сохранённые файлы остаются.
6. После проверки целостности получатель сохраняет результат. «Получено»,
   «Проверено», «Скачивание начато» и подтверждённое «Сохранено» не смешиваются.

## Обязательные требования

| ID | Контракт |
| --- | --- |
| FR-01 | Отдельный раздел с меткой Beta, существующие темы, широкий и узкий экран. |
| FR-02 | Выбор только принятых друзей. Каждый адресат отдельно принимает весь пакет; согласие на дружбу не является согласием на файлы. |
| FR-03 | Один или несколько файлов, кнопка выбора и desktop drag-and-drop; удаление из черновика. До «Отправить» не передаётся даже список файлов. |
| FR-04 | По умолчанию 5 000 000 000 байт (5 ГБ) на файл, 10 файлов на пакет, четыре получателя одновременно. Все три значения задаются сервером и видны в UI. |
| FR-05 | Превышение размера, количества файлов или получателей отвергается до приглашений. Изменение серверных настроек не требует пересборки клиента в пределах поддерживаемого диапазона. |
| FR-06 | Состав отправленного пакета неизменен. Новые файлы/адресаты требуют новой отправки и согласия. |
| FR-07 | Отдельное соединение и прогресс для каждого получателя. Медленный адресат, отказ или отмена не останавливают остальных. Лимит одновременных адресатов учитывает все активные отправки пользователя на этом устройстве. |
| FR-08 | Каждый файл у обеих сторон показывает, например, 37,42% и подтверждённый полезный объём. Повторные сетевые пакеты не увеличивают прогресс. У отправителя отображение может отставать на время ACK. |
| FR-09 | Кольцо вокруг иконки изначально пустое, плавно заполняется только по фактическому прогрессу. Текст процента обязателен. Reduced motion отключает интерполяцию, но не информацию. |
| FR-10 | Отмена конкретного адресата или всей отправки. Получатель отменяет собственное получение. Уже сохранённые файлы не удаляются дистанционно. |
| FR-11 | Пауза, докачка, восстановление после запуска и постоянная очередь не входят. Окончательный обрыв даёт понятную ошибку и необходимость новой отправки. |
| FR-12 | Ожидание согласия существует только в текущем сеансе с ограниченным сроком приглашения. Офлайн-получатель не получает файл позже с сервера. Закрытие панели не закрывает приложение и само по себе не отменяет передачу. |
| FR-13 | Предпочитать прямой ICE-путь, автоматически использовать TURN при необходимости. Сервер не хранит содержимое файлов. |
| FR-14 | При фактическом relay-пути отправитель постоянно видит заметное предупреждение рядом с конкретным получателем: «Прямое соединение не установлено. Файлы передаются через сервер-ретранслятор». Не заменять его tooltip или кратким toast. Предупреждение связано с фактическим маршрутом, обновляется при его изменении и доступно без различения цветов. |
| FR-15 | Получатель также видит режим соединения. Не объявлять путь прямым, пока статистика выбранной ICE-пары этого не подтверждает. |
| FR-16 | Защищённые авторизованные устройства, шифрование через прямое соединение и TURN, итоговая проверка целостности. Отзыв доступа останавливает передачу. |
| FR-17 | Потоковое чтение/запись, без загрузки файла/пакета целиком в RAM. До принятия оценить место под временные данные и экспорт; ошибку квоты/диска показать без ложного успеха. |
| FR-18 | 100,00% передачи не равно сохранению: отдельно показывать проверку и сохранение. Пустые файлы, одинаковые имена, Unicode и отмена сохранения обрабатываются корректно. |
| FR-19 | Передача не требует звонка, микрофона или камеры; совместимость с текущими звонками и обычными вложениями сохраняется. |
| FR-20 | Временные принятые данные очищаются после отмены/завершения сеанса и при следующем запуске после аварии; это технические остатки, не очередь докачки. Проверенную копию в текущем сеансе можно сохранить повторно без повторной передачи. |

## Принятые границы

Один отправитель передаёт отдельную копию каждому получателю: файл 2 ГБ для четырёх
получателей — примерно 8 ГБ полезных исходящих данных. Нет торрент-раздачи между
получателями, публичных ссылок, каталогов и облачного хранения. Файлы внутри
каждого получателя идут последовательно, получатели — параллельно.

Закрытое или выгруженное приложение не обязано передавать данные. Физических
Android/iPhone у пользователя сейчас нет: аппаратная приёмка остаётся отдельной
непроверенной частью; браузерная автоматизация и эмуляция не заменяют её.

Не проверено: реальная функция, максимальные размеры на разных платформах.
Существенные риски: квоты/экспорт больших файлов в браузерах и нагрузка TURN.

## Скорость передачи

Дополнение пользователя: у отправителя и получателя показывать независимую
скорость для каждой пары участников, в Б/с, КБ/с или МБ/с. Сглаживать полезные
подтверждённые байты за последние три секунды; повторные пакеты и ACK не удваивают
скорость. При отсутствии данных скорость падает до нуля. Проверить разные скорости
нескольких адресатов и одинаковую методику у обеих сторон.

## Визуальная схема передачи

Дополнение пользователя: показывать отправителя и каждого получателя с отдельной
линией и плавным движением маркеров данных между ними. Движение связано с реальным
поступлением подтверждений, прекращается при отсутствии данных/ошибке/отмене,
завершение получает статичную отметку. Схема дополняет скорость, проценты и
постоянное предупреждение TURN. Reduced motion сохраняет статическую схему.
