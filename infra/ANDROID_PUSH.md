# Android FCM

Клиент использует проект Firebase `voicechat-aa174`, package
`dev.voicechat.voicechat_probe` и клиентский `google-services.json`.
Клиентская конфигурация не содержит серверного private key.
FCM SDK и WorkManager закреплены в Android Gradle; auto-init выключен до
согласия на уведомления. Analytics не подключён.

## Секрет и выпуск

Серверный service-account JSON никогда не включать в Git, CI, образы,
release tarball, APK или логи. Локальный рабочий экземпляр находится вне
репозитория, с правами 0600. `.gitignore` и `.dockerignore` дополнительно
исключают характерные имена таких ключей.

Control читает ключ из `/work/.prototype/push/firebase-service-account.json`
в своём постоянном volume; каталог 0700, файл 0600, владелец UID/GID10001.
Устанавливать файл отUID10001 через stdin защищённого SSH/Docker exec, не через аргументы
команды или shell interpolation. Проверять права и совпадение project_id,
не печатая содержимое. Ключ не менять при каждом релизе.

При наличии файла включается Android gateway. Путь можно явно переопределить
`VOICECHAT_FCM_CREDENTIALS`; явно пустое значение отключает FCM, включая restore
на изолированном стенде. Изменение stand.env production имеет отдельный guard:
не редактировать runtime hashes/pointers ради его обхода. Обычный выпуск
использует ключ в существующем control volume без изменения stand.env.

Серверные изменения требуют `Build and deploy`, `mode=full`, `deploy=true`;
Android APK и macOS Sparkle-пакет публикуются отдельно. При backup ключ попадает
только в зашифрованную серверную копию control volume. Перед restore исключить
реальную отправку уведомлений. Старые клиенты продолжают Matrix-сигналинг;
для системного фонового звонка отправитель также должен быть обновлён.

## Контракт

- `POST /api/push/android`: register/remove с Matrix Bearer; user/device
  определяются через whoami, а не принимаются из тела запроса.
- Matrix pusher: `dev.voicechat.android`, `event_id_only`, случайный binding;
  callback использует существующий `/_matrix/push/v1/notify`.
- FCM HTTPv1 получает только binding и случайный notice. Текста, отправителя,
  room/session ID, SDP, ключей и URL вложений в FCM payload нет.
- Нативный Android через HTTPS/Bearer binding разрешает notice на сервере.
  Сервер проверяет существование Matrix-устройства и членство в комнате
  через защищённый внутренний Synapse resource `push-device`.
- Binding даёт только маршрутизацию уведомлений и отклонение адресованного
  ему входящего звонка; он не даёт доступа к Matrix, сообщениям или медиаключам.
- `POST /api/push/call`: invite/status/accept/decline/end с Matrix Bearer.
  Invite проверяет шифрование, членство, запрет личной комнаты и лимит аудитории.
  Accept атомарен для пользователя и устройства; чужой end запрещён.
- Исходящие call wakeups сохраняются в SQLite и повторяются после сбоя.
  Android WorkManager повторяет сетевые ошибки и обновляет FCM token
  через собственную binding-привязку. Logout/смена профиля очищают её локально;
  старый push не может снова включить уведомления.
- Сообщения хранятся для доставки до суток; вызов звонит максимум45 секунд.
  При каждом получении/нажатии проверяется текущее состояние. Cancel/answer/
  decline снимают уведомления на других устройствах. Дубли Matrix и call
  wakeup во время звонка разрешаются к одной call notification.
- Первые call events буферизуются до установки VoIP delegate при холодном запуске.
  Ответ выполняется только после обычной проверки устройств и E2EE-сигналинга.

## Android и границы проверки

Включить уведомления в меню приложения и разрешить их в Android. На Android14+
системное разрешение полноэкранных вызовов открывается отдельно; без него
используется системное уведомление с кнопками ответа и отклонения.
Звуки и Focus/Do Not Disturb подчиняются настройкам ОС. На старых Android
используются обычные notification actions, на API31+ — CallStyle.

Поверх keyguard открывается только нейтральный нативный экран звонка.
Переписка и Flutter-профиль не получают showWhenLocked. Перед переходом к
ответу ОС запрашивает обычную разблокировку, если телефон защищён.
Видео явно обозначено до ответа; тип из push-состояния сверяется с
шифрованным приглашением, несовпадение требует ответа в самом приложении.
На Android7 срок уведомления дополнительно снимается системным alarm:
платформенный Notification timeout появился только на Android8.

Выход ждёт завершения отправленного invite и соответствующего cancel до
закрытия транспорта. Поздний ответ/таймер старого вызова не завершает новый.

Требуются Google Play Services. Удаление приложения из недавних не равно
«Остановить принудительно»: после force-stop ОС не обязана доставлять FCM
до ручного открытия. Производители могут дополнительно ограничивать фон.
Нельзя обещать абсолютную доставку без сети, разрешений и при ограничениях ОС.

Автотесты проверяют привязки/отзыв/членство/дубли/ретраи/отмену/атомарный ответ,
OAuth подпись и приватность FCM payload, выход во время регистрации и события
холодного запуска. Сборка, API-проба и эмулятор не закрывают физическую приёмку.
Её единственный актуальный реестр — `docs/user-acceptance.md`, UA-18.
